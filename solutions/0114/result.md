## 三个版本的演进（用户两版 + 标准版）

| 版本 | 思路 | 时间/空间 | 备注 |
|------|------|----------|------|
| v1 | 前序收集节点引用 → 全 left=None → 连 right | O(n) / O(n) | 正确直观，不满足 O(1) 进阶 |
| **v2（定稿，用户）** | 原地插接 + `find_max_right` 递归找"左子树展开后链尾" | **O(n²)** / O(1) | 力扣通过 0ms/100% |
| solution_readable | 标准版：沿 right 链找尾 | **O(n)** / O(1) | 优化参考 |

## v2 的实测数据（用户优化的真实效果与边界）

- **正确性满分**：5 万组随机树 0 错误（顺序 + left 清空双检查）；与标准版 5 万组完全一致；
- **效率**：左链 600 节点 v2 11.79ms vs 标准 0.03ms（**慢 440 倍**，O(n²) vs O(n)）；满树 1023 慢 2.3 倍；
- **⚠️ 边界风险**：`find_max_right` 递归深度 = 树高，左链 >1000 节点会 **RecursionError**（力扣约束 ≤2000，全左链极端用例有风险——本次测例未触发，已通过）。

## v2 的设计亮点（保留原因）

- 找"左子树**展开后**的链尾"（= 前序遍历最后一个节点）——比标准解法"沿 right 链"更好理解、更通用；
- 用户自悟：`ori = root` 不需要——`flatten` 只改节点内部指针，`root` 只是局部变量在移动，不影响调用者持有的头节点引用。
