# 108. 将有序数组转换为二叉搜索树 · 解析

## 题目简述

给你一个**升序排序**的整数数组 `nums`，将其转换为一棵**高度平衡**的二叉搜索树（BST 中序遍历 = 原数组，且每个节点左右子树高度差 ≤ 1）。

示例：`[-10,-3,0,5,9]` → `[0,-3,9,-10,null,5]`（答案不唯一，special judge）。

## 核心套路：分治 + 中点取根（"平衡靠构造，不靠检查"）

**为什么用中点取根**：要满足"左右子树高度差 ≤ 1"，最简单的方式是让**左右子树的元素数量尽量相等**——取中点为根，左右各半，长度差 ≤ 1，数学上直接保证平衡。

```python
class Solution:
    def sortedArrayToBST(self, nums):
        if not nums:
            return None
        mid = len(nums) // 2
        root = TreeNode(nums[mid])
        root.left = self.sortedArrayToBST(nums[:mid])       # 左边比中点小
        root.right = self.sortedArrayToBST(nums[mid + 1:])  # 右边比中点大
        return root
```

**这是"构造性证明"**：我们不是在构造完以后检查是否平衡（那是 110 题），而是**每一步的构造方式本身就保证平衡**——分治的递归深度处处相差 ≤ 1。

**递归三要素**：
- 基线：空数组（lo > hi）→ None；
- 递推：中点作根、左半递归、右半递归；
- BST 性质自动满足：左半所有值 < 中点 < 右半所有值（数组有序）。

## ⚡ 进阶：传下标区间，免切片拷贝（O(n log n) → O(n)）

用户版用切片，每层 `nums[:mid]` / `nums[mid+1:]` **各拷贝 O(k)**——总时间 O(n log n)（n=10⁴ 力扣无压力，但面试常追问优化）。

**传 `lo/hi` 下标不拷贝，每个元素只访问一次 → O(n)**：

```python
class Solution:
    def sortedArrayToBST(self, nums):
        def fun(lo, hi):
            if lo > hi:
                return None
            mid = (lo + hi) // 2
            root = TreeNode(nums[mid])
            root.left = fun(lo, mid - 1)
            root.right = fun(mid + 1, hi)
            return root
        return fun(0, len(nums) - 1)
```

**进阶关键**：把"子数组"从**切片拷贝**换成**下标区间**（`lo..hi`），递归时只传两个整数——空间也顺便省了每层的临时列表。

## 细节解答

- **`nums[mid+1:]` 越界吗**？不会——`mid+1 == len(nums)` 时切片为 `[]`，fun 返回 None（Python 切片静默截断）；
- **偶数长度取哪个中点**？`len // 2` 取偏右（如 `[0,1,2,3]` → mid=2），力扣 special judge 允许多种合法答案。

## 复杂度

| 版本 | 时间 | 空间（不含结果） |
|------|------|-----------------|
| 切片版（用户） | O(n log n) | O(log n) 递归栈 |
| **下标版（进阶）** | **O(n)** | O(log n) 递归栈 |

## 考点

- 分治构造（反向分治：98 是"检查"、108 是"构造"）
- **构造性平衡**（中点劈半 → 数学保证高度差 ≤1）
- Python 切片 vs 下标区间（常数/复杂度优化意识）
- BST 中序 = 有序数组（98/108/230 三题共用的核心性质）

## 易错点

1. 不取中点（比如取第一个元素）→ 退化成斜树，不平衡；
2. 切片越界不需要特殊处理（Python 语义），但**传下标版必须 `lo > hi` 判基线**（否则死循环）；
3. `mid + 1` 用于右半起点（别漏 +1，会无限递归）；
4. 空数组要返回 None（不是报错）。
