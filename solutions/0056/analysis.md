# 56. 合并区间 · 解析

## 题目简述

以数组 `intervals` 表示若干个区间的集合，合并所有重叠的区间。

示例：`[[1,3],[2,6],[8,10],[15,18]]` → `[[1,6],[8,10],[15,18]]`。

## 核心套路：排序 + 一次线性扫描

**先按左端点排序**——这是本题的关键动作，带来两个好处：

1. **可重叠的区间一定相邻**：排序后，重叠只会发生在"相邻"区间之间（或与已合并区间之间）,不需要两两检查；
2. **左边界天然有序**：后续区间的左端点一定 ≥ 前面所有区间的左端点，合并时左边界无需计算。

然后线性扫描：当前区间与 `result` 最后一个区间比较——

- **有重叠**（`新区间左 ≤ 已合并区间右`）：合并，只更新右边界；
- **无重叠**：直接追加为新段。

## 定稿解法

```python
class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        length = len(intervals)
        intervals.sort(key=lambda x:x[0])
        result = [intervals[0]]
        for i in range(length-1):
            if intervals[i+1][0] <= result[-1][1]:
                result[-1][1] = max(intervals[i+1][1], result[-1][1])
            else:
                result.append(intervals[i+1])
        return result
```

### 为什么合并时只需要更新右边界（不需要 min）

因为**按左端点排序了**：`intervals[i+1][0] >= ... >= intervals[0][0]`，而 `result[-1][0]` 始终是这批合并区间的最小左端点（就是第一个区间的左端点）。所以：

```
合并后左边界 = result[-1][0]（沿用，无需计算）
合并后右边界 = max(result[-1][1], 新区间右)
```

初始的 `result[-1] = [min(...), max(...)]` 写法里的 `min` 在 100% 的情况下返回旧左边界——**白算**。

### 复杂度

- 时间 **O(n log n)**：排序主导，扫描 O(n)；
- 空间 **O(n)**：result 结果数组（排序若原地则是 O(log n) 栈或 O(1) 辅助，取决于语言）。

## 两个值得记住的写法细节

1. **就地更新 vs 新建对象**：`result[-1] = [a, b]` 每次合并都创建新列表（内存分配 + 引用替换）；`result[-1][1] = b` 只改列表的一个槽位，快且省。重叠越多差距越大（实测快 35%）。
2. **`sort()` vs `sort(key=lambda x: x[0])`**：Python 列表默认按元素顺序比较（先比第一个元素），`sort()` 直接等价于按左端点排，省掉 key 函数调用。若还要按右端点排才需要显式 key。

## 考点

- 区间问题的通用第一步：**排序**（合并区间、插入区间 57、会议室 252、重叠区间计数等）
- 重叠判断条件（`新区左 ≤ 旧区右`，注意边界相等也算重叠）
- 常数值优化意识：复用对象、去掉无意义计算
- 与第 15 题（三数之和）呼应：**排序带来的有序性**让后续判断/去重/合并全部简化

## 边界注意

- 输入已按左端点排好序也要自己排（不能假设有序）；
- 相等边界 `[[1,4],[4,5]]` → 重叠合并为 `[1,5]`（条件用 `<=`）；
- 空输入 / 单区间直接返回。
