# 104. 二叉树的最大深度 · 解析

## 题目简述

给定二叉树根节点 `root`，返回其最大深度（根到最远叶子节点的路径上的节点数）。

## 核心套路：递归（分治思想，树题第一板斧）

**最大深度 = 1（根自己）+ max(左子树深度, 右子树深度)**——递推式就是答案。

```python
class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0
        return 1 + max(self.maxDepth(root.left), self.maxDepth(root.right))
```

- **基线**：空树深度 0；
- **递推**：非空 = 1 + 左右较深的那棵。

**分治视角**：把"求整棵树深度"拆成"求左右子树深度"两个子问题，各自解决后合并（取 max + 1）——树的递归题基本都是这个模式（226 翻转、101 对称、543 直径都是）。

## 用户原版（deep 传参版，等价但常数略大）

```python
class Solution:
    def maxDepth(self, root):
        if not root:
            return 0
        return self.scan(root)

    def scan(self, root, deep=1):
        if root:
            return max(self.scan(root.left, deep=deep + 1),
                       self.scan(root.right, deep=deep + 1))
        return deep - 1
```

**思路**：把深度"提前算好"一路带下去（每层 deep+1），空节点返回 deep-1（空节点不计深度，返回上一层节点的深度）。

**为什么慢 ~48%（实测 11.87 vs 7.99 ms @ 13 万节点）**：
1. 每层递归都多传一个 `deep` 参数，且 `deep+1` 每次新建整数对象；
2. 空节点要做 `deep-1` 运算（经典版空节点直接返回 0，零运算）；
3. 思路多绕一层（"带深度下去" vs "上来再 +1"）。

**但复杂度同为 O(n)**——这只是常数差异，不是算法问题。

## 击败率陷阱（本题最重要的认知）

| | 用户 deep 版（网页） | 经典版（leetgo） |
|--|--------------------|-----------------|
| 提交成绩 | 击败率低 | **7ms/12%、内存 7%（也低！）** |

**结论**：经典版提交击败率同样低——证明 104 这种题**击败率完全不可信**：

- 所有解法都是 O(n)，差距只有几十微秒的常数；
- 力扣"进程总耗时 + 噪声"（240 题知识点）在 0~几 ms 区间被放大；
- **判断解法好坏看复杂度，不看击败率**——简单题尤其如此。

## 复杂度

- 时间 **O(n)**（每节点访问一次）；
- 空间 **O(h)** 递归栈（最坏 O(n) 斜树；Python 递归上限 ~1000 层，超深树用迭代 BFS/DFS）。

## 考点

- 树的分治递归模式（本题是**最简单样板**：104 → 110 平衡二叉树 → 543 直径 都是它的变体）
- 递归基线 + 递推式
- 空间口径与击败率陷阱

## 易错点

1. 空树返回 0（不是 None）；
2. `max` 两个子树——漏掉 max 会返回"左+右"（那是节点数不是深度）；
3. 深树递归栈溢出（可用迭代版兜底）。
