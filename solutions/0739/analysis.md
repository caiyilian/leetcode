# 739. 每日温度 · 解析

## 题目简述

每天一个温度，返回"再过几天会遇到更高温度"（没有则 0）。如 `[73,74,75,71,69,72,76,73]` → `[1,1,4,2,1,1,0,0]`。

## 核心套路：单调栈（下一个更大元素的"距离版"）

**暴力**：每天往后找更高温 O(n²)。**单调栈**：维护一个"栈顶最小"的递减栈（温度从栈底到栈顶单调递减），每来一个更大温度就把栈里所有比它小的**结算掉**：

```
73 → 栈[0]
74 → 73 被顶：result[0]=1-0=1 → 栈[1]
75 → 74 被顶：result[1]=2-1=1 → 栈[2]
71 → 入栈 → 栈[2,3]
69 → 入栈 → 栈[2,3,4]
72 → 69被顶 result[4]=5-4=1；71被顶 result[3]=5-3=2；75更大停 → 栈[2,5]
...
result = [1,1,4,2,1,1,0,0] ✅
```

```python
class Solution:
    def dailyTemperatures(self, temperatures):
        length = len(temperatures)
        index_stack = []              # 存下标
        result = [0] * length         # 全 0 初始化

        for i in range(length):
            while index_stack and temperatures[index_stack[-1]] < temperatures[i]:
                result[index_stack[-1]] = i - index_stack[-1]
                index_stack.pop()
            index_stack.append(i)
        return result
```

**三个设计点**：

1. **栈存下标不存值**（★ 本次卡点）：结算公式 `i - idx` 需要下标；判断时用 `temperatures[stack[-1]]` 取值；
2. **result 定点填**：弹出谁给谁填（`result[idx] = ...`），而不是顺序 append——**结果数组位置固定，谁被结算就写谁的格子**；
3. **全 0 初始化**：栈里剩到最后的（= 后面没有更高温）保持 0，天然正确。

**为什么 O(n)**：每个下标入栈一次、出栈最多一次——**每个元素被访问常数次**，总 O(n)。这就是单调栈"用一次遍历记录所有答案"的威力。

## ⚠️ 用户走过的弯路（存值版失败分析）

用户的半成品（力扣前版）：栈存温度值，`count` 数"弹了几个"当距离：

```
问题1：距离 ≠ 弹出的个数——弹出元素间可能隔着已结算的项（下标差才对）
问题2：result 顺序 append 会错位——result[k] 必须由第 k 天固定占据
根因：存了"值"就丢掉了"位置信息"，而距离题恰恰要位置
```

**记忆锚点：凡是答案要"跨度/距离/下标差"的题（739/84/42/496），单调栈一律存下标。**

## 复杂度

- 时间 **O(n)**；空间 **O(n)**。

## 考点

- 单调栈模板（"下一个更大元素"家族：739 → 496/84/42）
- 存下标 vs 存值（结算跨度类题的关键决策）
- 定点填结果 + 全 0 兜底

## 易错点

1. **栈存值**（本次卡点——只判断不结算时没问题，一结算就露馅）；
2. `while stack and ...` 忘记判空（空栈访问栈顶 IndexError）；
3. 结算条件 `<=` 写成 `<`（等于时**不**顶掉——73,74,75 中两个 74 之间第一个 74 的答案应指向后面，严格小于才合理；题解用的严格小于）；
4. result 顺序追加导致的错位。
