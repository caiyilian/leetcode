## 关键优化

1. **增量维护（最大收益）**：窗口滑动只改变两个字符（移出最左 + 进入最右），计数数组每步只做 -1/+1，不再每次 26 次 × O(p) 重新 count；
2. **last_match 剪枝**：上一窗口已匹配时，若新进字符 == 移出字符，计数不变，直接记录，跳过比较；
3. **推理优化**：last_match 且首尾字符不同时，计数必然改变（`P - a + b ≠ P ⟺ a ≠ b`），本窗口必然不匹配，连比较都省了。

## 关于「== 比较」的性能（C 层 vs Python 层）

代码中每步用 `count_list_s == count_list`（两个长度 26 的列表比较）判断是否匹配：

- 单次 `==` 仅约 **33 纳秒**（C 层实现，26 个 int 一次比较完，与 n 无关）；
- 理论更优的「diff 差异计数法」（每步 O(1) 维护"多少个位置不等"）实测反而慢 **2 倍**（15ms vs 8ms）——因为 diff 每次更新要写 4 个 Python if 分支，Python 字节码远慢于 C 层 memcmp 级比较；
- **结论**：Python 中 `==` 已是实际最优，无需再优化。心法：能用 C 层内置操作（`==`/`sorted`/`count`/`join`）就少写 Python 手写逻辑。
