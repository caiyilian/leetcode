# 240. 搜索二维矩阵 II · 解析

## 题目简述

编写一个高效的算法来搜索 `m × n` 矩阵中的一个目标值 `target`。矩阵具有以下性质：
- **每行的元素从左到右升序**排列；
- **每列的元素从上到下升序**排列。

示例：`[[1,4,7,11,15],[2,5,8,12,19],[3,6,9,16,22],[10,13,14,17,24],[18,21,23,26,30]]` 中搜索 5 → true。

## 核心套路：右上角阶梯搜索（O(m+n) 最优解）

**关键观察**：右上角的元素 `matrix[i][j]` 有一个独特地位——**它是所在行的最大值、所在列的最小值**（因为行从左到右递增、列从上到下递增）。

于是它是个完美的"拐点"：

```
matrix[i][j] == target  → 找到了
matrix[i][j] >  target  → 整列都比 target 大 → 左移一列（j -= 1）淘汰整列
matrix[i][j] <  target  → 整行都比 target 小 → 下移一行（i += 1）淘汰整行
```

每走一步**淘汰一行或一列**，最多 `m+n` 步必定结束。

## 定稿解法

```python
class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        m, n = len(matrix), len(matrix[0])
        i, j = 0, n - 1          # 从右上角出发
        while i < m and j >= 0:
            if matrix[i][j] == target:
                return True
            if matrix[i][j] > target:
                j -= 1           # 淘汰当前列
            else:
                i += 1           # 淘汰当前行
        return False
```

### 正确性直觉

- 向左淘汰列：`matrix[i][j] > target` 时，该列所有元素（`matrix[i][0..j]` 及以上）都 ≥ `matrix[i][j]` > target——整列没戏，安全剔除；
- 向下淘汰行：`matrix[i][j] < target` 时，该行所有元素（`matrix[i][j..n-1]` 及以下）都 ≤ `matrix[i][j]` < target——整行没戏，安全剔除；
- 每步排除一整行/列且**永不再回头看**（指针只单向移动），不会漏。

## 复杂度

- 时间 **O(m+n)**：最多 m+n 步，理论最优（信息量下界）；
- 空间 **O(1)**。

## 力扣计时陷阱（本题最重要的课外收获）

用户实测困惑：暴力 O(mn) 与右上角 O(m+n) 在力扣都报 ~150ms，为什么？

**答案：力扣 runtime = 整个进程时间 = 解释器启动 + 输入解析 + 框架开销 + 算法耗时**。

| 开销项 | 估算 |
|--------|------|
| Python 解释器启动 | ~50ms |
| 300×300 矩阵 JSON 解析 | ~50-80ms |
| 框架 / GC / 收尾 | ~20ms |
| **算法本体**（暴力 1.8ms / 右上角 0.03ms） | ≤2ms |

固定成本 ~150ms 完全淹没算法差距（1.7ms），所以两个方法都报 148/150ms（leetgo 提交甚至 207ms 纯属机器波动）。

**铁律**：
1. 力扣 ms / 击败率是"进程总耗时"，**不能判断算法优劣**；
2. 判断复杂度靠**大 O 分析**，验证速度靠**本机基准**（本项目每题的"对拍 + 测速"脚本）；
3. 机考/面试中，遇到"为什么两种写法成绩一样"的疑问，想想固定开销。

## 考点

- 有序矩阵的**阶梯搜索**（右上角/左下角出发，每步淘汰一行/列）——240 的灵魂，面试必考
- 与 74 题（搜索二维矩阵 I，整矩阵行间也有序 → 可二分）的区分：
  - **74**：每行第一个 > 上一行最后一个（全局有序）→ 展平二分 O(log(mn))；
  - **240**：只保证行内/列内有序 → 右上角 O(m+n)。
- 淘汰思想（每步排除不可能区域，双指针单调移动）
