# 11. 盛最多水的容器 · 解题解析

> 用户独立完成，共 4 次迭代：暴力剪枝（超时）→ 标准双指针（定稿）→ 跳跃优化（出错）→ 跳跃修正（正确但收益不稳定）。
> 本解析重点记录**双指针的正确性证明**——这是本题真正的知识内核。

## 一句话思路

左右指针从两端向中间收缩，每轮算出当前面积，然后**移动较矮的那一侧**。
每轮都能排除一整批不可能的组合，O(n) 完成。

## 最终实现（v2）

```python
class Solution:
    def maxArea(self, height: List[int]) -> int:
        area = 0
        l, r = 0, len(height) - 1
        while l < r:
            if height[l] <= height[r]:
                area = max(height[l] * (r - l), area)
                l += 1
            else:
                area = max(height[r] * (r - l), area)
                r -= 1
        return area
```

- **时间 O(n)**：两个指针合计移动 n 次
- **空间 O(1)**：只需两个下标和结果变量

## ⭐ 正确性证明（为什么不会漏掉最优解）

### 每轮循环做的三件事

1. **算出一个候选答案**：当前 (l, r) 的面积；
2. **提供数学证明**：某一侧的其他所有搭配都不可能更好；
3. **基于证明移动到那一侧**（把该边界"淘汰出局"）。

第 2 步是核心——**不是猜，是证明**。

### 核心不等式

设当前 `h[l] ≤ h[r]`（左边为矮侧）。对任意中间的 `r'`（`l < r' < r`）：

```
面积(l, r') = (r' - l) × min(h[l], h[r'])

   其中：① 宽度 (r' - l) < (r - l)         ← r' 更靠近 l，宽度必然更小
        ② min(h[l], h[r']) ≤ h[l]         ← min 取较小者，h[l] 是其中之一
                                            （只要 l 不动，高度就被 h[l] 卡死）

   ⇒ 面积(l, r') ≤ (r' - l) × h[l] < (r - l) × h[l] = 面积(l, r)
```

**结论**：以 `l` 为边界的**任何**组合都严格小于当前值 → **l 的最优已经找到，可以退休**，一个可能的更优解都没漏。

### 直觉：矮的那根是"水面天花板"

- 水面高度 = `min(两侧)` = 矮的那根 → 它决定了水位上限；
- 向中间收缩，宽度只会变小 → **面积要变大，只能靠抬高天花板**；
- 抬高天花板的唯一方式 = **把矮的那根换掉** → 所以移动矮侧；
- 移动高侧是纯亏：宽度小了，天花板还纹丝不动。

### 全局为什么不出错

整个算法是"**逐步淘汰**"：所有 `C(n,2)` 个候选组合，要么被算过，要么被证明不如某个已算出的值。
窗口 `[l, r]` 内剩余组合由后续轮次继续考察 → **不存在"未评估且未排除"的漏网组合**。

### ⚠️ 关键区分：「移动」≠「跳过」

> 移动某侧的理由**不是**"新位置一定更好"，而是**"旧位置已经穷尽"**。
> 新位置是全新候选，其最优解尚未找到，**必须让它完整参与比较**。

用户 v3/v4 的跳跃优化正是在这里出错：把"新位置较矮"当成了"可以跳过"的理由。
**"矮"从来不是淘汰依据，"已被证明穷尽"才是**——这是"有证明的排除"与"凭感觉的跳跃"的分界线。

## 四版演进与实测数据

### v1：暴力 + 剪枝（2000 组随机数据验证**逻辑正确**）

| 数据形态 n=1500 | v1 剪枝版 | v2 双指针 | 倍数 |
|:---:|:---:|:---:|:---:|
| 递减 | **131.3 ms** | 0.105 ms | **1253x** |
| 峰形 | 63.6 ms | 0.108 ms | 590x |
| 递增 | 0.212 ms | 0.106 ms | 2x |
| 随机 | 0.599 ms | 0.095 ms | 6x |

**教训**：剪枝算法的性能**依赖数据分布**，最坏情况无法保证 → 力扣用"针对剪枝构造"的用例把它击穿。
双指针版在**所有**数据形态下恒定 0.095 ms——O(n) 的意义正在于"最坏情况可控"。

### v3：跳跃优化（条件写错对象）—— ❌ 错误

最小反例：`[2, 4, 2, 8]` → 返回 6，正确答案 8
（最优解来自 `(l=1, r=3) = 2 × min(4,8) = 8`，而跳跃把 l=1 跳掉了）。

### v4：跳跃优化（条件修正 `now_l >= height[l]`）—— 正确但收益不稳定

| 数据形态 n=2000 | v2 标准版 | v4 跳跃版 | 对比 |
|:---:|:---:|:---:|:---:|
| 递减 / 递增 / 峰形 | ~0.124 ms | 0.168~0.202 ms | **慢 24~40%** |
| 全相等 / 随机 | ~0.127 ms | 0.069 ms | 快 1.75~1.92x |

10000 组随机数据零错误。但：力扣上两者**同为 0ms**（差异被计时精度与噪声吞没），
且代码复杂度、正确性论证成本都显著上升 → **未采用**（过早优化的典型案例）。

## 本题考点

| 考点 | 内容 |
|------|------|
| 双指针（对撞） | 左右收缩 + 移动矮侧 |
| 正确性证明 | 核心不等式 `面积(l,r') < 面积(l,r)` |
| 支配/淘汰思维 | 每轮排除一整批组合，而非枚举 |
| 最坏情况意识 | 剪枝依赖数据分布；O(n) 的价值是可控上界 |
| 过早优化的代价 | v3/v4 的收获远小于代码复杂度与风险增长 |
