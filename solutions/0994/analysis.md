# 994. 腐烂的橘子 · 解析

## ⚡ 用户自学关键点：多源 BFS（"同时腐烂"怎么表达）

用户原话困惑："有可能有多个腐蚀的橘子同时开始腐蚀"——**这是本题唯一的新概念**，答案就是多源 BFS。

## 题目简述

网格中 `0` 空、`1` 新鲜、`2` 腐烂。每分钟腐烂橘子感染上下左右的新鲜橘子。求全部腐烂所需**最少分钟数**，若永远烂不完返回 `-1`。

## 核心套路：多源 BFS（层数 = 分钟）

**为什么"多源"**：多个腐烂橘子同时开始腐烂——单独对每个 '2' 做 BFS 再取 min 是错的（会重复计数、逻辑混乱）。正确做法：**把所有 '2' 一次性全部放入队列（作为第 0 分钟）**，BFS 天然按层扩散——"层"就是"分钟"。

```python
class Solution:
    def orangesRotting(self, grid):
        use_time = 0
        m, n = len(grid), len(grid[0])
        q = deque()
        fresh = 0
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 2:
                    q.append((i, j, 0))        # ① 多源入队：所有腐烂橘子，分钟 0
                elif grid[i][j] == 1:
                    fresh += 1                 # ② 新鲜橘子计数
        while q:
            i, j, use_time = q.popleft()
            for ni, nj in [(i, j-1), (i, j+1), (i+1, j), (i-1, j)]:
                if ni < 0 or ni >= m or nj < 0 or nj >= n or grid[ni][nj] in (0, 2):
                    continue
                grid[ni][nj] = 2               # ③ 感染 + 原地标记（200 题沉没技巧）
                fresh -= 1
                q.append((ni, nj, use_time+1)) # ④ 队列带 minutes
        if fresh != 0:
            return -1                          # ⑤ 还有新鲜橘子 → 永远烂不完
        return use_time                        # ⑥ 最后一次出队时间 = 总分钟
```

## 五个设计点的"为什么"

1. **为什么所有 '2' 同时入队**：BFS 的队列天然按层出队——两个源头在第 0 分钟都在队列里，第 1 轮一起感染各自的邻居，"同时性"由队列结构保证；
2. **为什么队列带 `use_time`**：BFS 分层（102 题的 `len(q)` 快照）可以数层数，但每个橘子被感染的时间不同，把 `minute` 跟着坐标一起存进队列最直观——**最后出队的那个橘子的时间就是总分钟**；
3. **为什么 `fresh` 计数**：判断 -1 的标准——BFS 结束后还有没被感染的新鲜橘子（被 0 隔离），`fresh != 0` 就返回 -1；
4. **为什么 `grid[ni][nj] in (0, 2)` 跳过**：水和已腐烂的都不用再处理（已腐烂的不重复感染）；
5. **为什么原地改成 '2'**：200 题的"沉没"技巧——感染过的橘子变成腐烂的，天然防止重复处理（不需要 visited 数组）。

## 边界情况（面试自查）

| 网格 | 结果 | 原因 |
|------|------|------|
| `[[0,2]]` | 0 | 没有新鲜橘子，一分钟都不用等 |
| `[[1]]` | -1 | 没有腐烂橘子当源头 |
| `[[2],[1]]` | 1 | 一分钟后全烂 |
| 全 `[[0]]` | 0 | 无橘子 |
| 被 0 隔开的新鲜橘子 | -1 | 永远够不着 |

## 和 200 岛屿数量的对比（图论两板斧）

| | 200 岛屿数量 | 994 腐烂的橘子 |
|--|------------|---------------|
| 遍历方式 | **DFS（沉没）** | **BFS（层序分钟）** |
| 源数量 | 单源（每次遇到才 DFS） | **多源（全部入队）** |
| 时间语义 | 无（只数连通块） | **层数 = 分钟** |
| 队列内容 | 无队列 | `(i, j, minute)` |

**记忆锚点**："要数几个 → DFS"、"要算几分钟 → BFS 多源"。

## 复杂度

- 时间 **O(m×n)**（每格最多入队一次）；空间 **O(m×n)**（队列最坏存全部橘子）。

## 考点

- **多源 BFS**（本题核心，也是 1162 地图分析、多源最短路系列的前置）
- 队列带状态的技巧（`(i, j, minute)`）
- 网格四连通 + 越界检查（200 题复用）
- 原地标记防重复（200 题复用）

## 易错点

1. **对每个 '2' 单独 BFS**——多源必须一起入队，否则"同时性"丢失；
2. `fresh` 忘记维护（-1 判断依赖它）；
3. 没有腐烂橘子且没有新鲜橘子（全是 0/2）→ 返回 0（不是 -1）；
4. 边界 `[[1]]`（无源头）→ -1，别写崩；
5. deque 别忘了 import（leetgo 模板没有，本地测试 NameError 坑）。
