# 33. 搜索旋转排序数组 · 解析

## 题目简述

有序数组在某点旋转（如 [0,1,2,4,5,6,7] → [4,5,6,7,0,1,2]），元素互异。O(log n) 找 target 下标。

## 核心套路：一次二分，判断 mid 落在哪段（不求旋转点！）

**灵魂洞察**：数组只有一个旋转点（一个"断裂"）→ **每次二分，mid 必然落在"左升序段"或"右升序段"之一**：

```
[4,5,6,7,0,1,2]  mid=3(7)：nums[l]=4 <= 7 → mid 在左升序段 ✅
[4,5,6,7,0,1,2]  mid=5(1)：nums[l]=4 <= 1? 否 → mid 在右升序段 ✅
```

**判据**：`nums[left] <= nums[mid]` → 左段 [left..mid] 有序；否则右段 [mid..right] 有序。

**然后每步只问一个问题：target 在不在"有序的那段"里？**（在 → 常规二分往里走；不在 → 去另一半——另一半乱序但含断裂，递归同样适用）

```python
class Solution:
    def search(self, nums, target):
        left, right = 0, len(nums) - 1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                return mid
            if nums[left] <= nums[mid]:        # ① mid 在左升序段
                if nums[left] <= target < nums[mid]:
                    right = mid - 1            # target 在左段范围内 → 左走
                else:
                    left = mid + 1             # 不在 → 去右（断裂侧）
            else:                               # ② mid 在右升序段
                if nums[mid] < target <= nums[right]:
                    left = mid + 1             # target 在右段范围内 → 右走
                else:
                    right = mid - 1            # 不在 → 去左（断裂侧）
        return -1
```

**为什么收敛**：旋转点被"夹"在中间，每轮二分必然把搜索范围减半（要么进有序段，要么进含断裂的另一半），O(log n)。

## ⚠️ 走过的弯路：为什么"显式求 k"路线必炸（三次失败实录）

**用户的原始构想**（力扣 749738051/180/654 三次失败）：

```python
while nums[left] > nums[right]:   # ① 双指针夹逼求旋转点 k
    left += 1
    right -= 1
k = left
# ② 再搞"逻辑一维二分" nums[mid-k] ... 最后映射回原数组
```

**三个独立炸弹**（逐个分析）：

1. **夹逼求 k 不可靠**：旋转点位置任意，两端夹逼只在恰好对称时碰巧命中。未旋转数组直接算成 k=length、部分旋转算错值 → 后续全错（WA）；
2. **逻辑二分 `nums[mid-k]` 的负索引**：mid < k 时 mid-k 为负，Python 负索引取**尾部元素**——彻底错乱，且肉眼极难发现；
3. **返回映射越界**：未旋转且找不到 target 时 left 收敛到 length，`nums[left-k] = nums[length]` → **IndexError（RE）**；加上 `% length` 修好后，夹逼 k 本身错 → 依然 WA。

**终极教训（比解法本身更值钱）**：

> **当一个问题需要"先求中间量 k、再拿 k 去做映射"时，先问自己：能不能绕开 k？**
> 旋转数组二分的标准解根本不需要知道旋转点在哪——"mid 在哪段"这个二选一判断天然蕴含了全部信息。
> 求 k 的路线 = 引入一个"中间状态" = 多一个出错面（求错 / 映射错 / 越界，三次失败各踩一个）。

**识别信号**：凡是二分 + 下标变换（`mid-k`、`(x+n)%n`、坐标映射）的组合，都要警惕"中间量是否稳定可求、映射是否越界"——74 题的 `mid//n` 教训同族。

## 复杂度

- 时间 **O(log n)**；空间 **O(1)**。

## 考点

- **段判断二分**（旋转数组的灵魂技巧，153 最小值同源）
- 区间嵌套判断（`nums[left] <= target < nums[mid]` 的链式比较）
- 不求中间量、利用二选一结构（避免"显式求 k"陷阱）

## 易错点

1. **试图显式找旋转点**（本次三次失败的根源）；
2. 段判断 `nums[left] <= nums[mid]` 用 `<`——元素互异但 mid==left 时 = 成立（区间 2 元素），漏了会误判段；
3. 链式比较边界：左段 `nums[left] <= target < nums[mid]`、右段 `nums[mid] < target <= nums[right]`——`<` 和 `<=` 别写反（target 等于端点时语义不同）；
4. 闭区间 while `left <= right` + `mid±1`（和 35 开区间不同，两套都行但别混）；
5. 未旋转（k=0）case 别特殊处理——标准解天然兼容（nums[left] <= nums[mid] 恒真，退化为普通二分）。
