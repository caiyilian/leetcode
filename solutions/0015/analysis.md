# 15. 三数之和 · 解题解析

> 用户从"没思路"起步，经降维提示自行写出解法，独立推导出去重的本质（Δj+Δk=0），
> 并在此基础上完成剪枝与微优化。最终提交击败 92%。

## 一句话思路

**降维**：固定第一个数 `nums[i]`，问题就变成在剩余区间里找「两数之和 = -nums[i]」，
再用左右双指针（第 11 题学过的）在**有序数组**里 O(n) 求解。

## 最终实现

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        n = len(nums)
        res = []
        for i in range(n - 2):
            target = nums[i]
            if target > 0:                        # 剪枝：最小的数都 > 0
                break
            if i > 0 and target == nums[i - 1]:   # i 侧去重
                continue
            j, k = i + 1, n - 1
            while j < k:
                left, right = nums[j], nums[k]
                s = target + left + right
                if s < 0:
                    j += 1
                elif s > 0:
                    k -= 1
                else:
                    res.append([target, left, right])
                    j += 1
                    k -= 1
                    # 两侧值同时不变才是重复（Δj = Δk = 0），同步跳过
                    while j < k and nums[j] == left and nums[k] == right:
                        j += 1
                        k -= 1
        return res
```

- **时间 O(n²)**：外层 O(n) × 内层双指针 O(n)
- **空间 O(1)**（忽略排序与返回值）

## ⭐ 去重的本质：Δj + Δk = 0（用户独立推导）

命中解 `(i, j, k)` 后，看下一个候选 `(j+1, k-1)`：

```
新和 = nums[i] + nums[j+1] + nums[k-1]
     = 0 + Δj + Δk        （Δj = nums[j+1]-nums[j] ≥ 0，Δk = nums[k-1]-nums[k] ≤ 0）
```

- 新和 = 0 且是**重复三元组** ⟺ `Δj = 0 且 Δk = 0`（两侧值都没变）；
- 若 `Δj > 0 且 Δk = -Δj`，新和也为 0，但**三元组的值变了** → 是**新解**，应记录。

**结论：重复的唯一来源是"两侧同时不变"**——这就是去重条件写 `nums[j]==left and nums[k]==right`
（同步跳过）的依据，比标准的"分别跳"更精确，实测也更快（见下）。

## 三个关键优化

### 1. 剪枝（收益最大）

```python
if target > 0: break     # 排序后最小的数都 > 0 → 三个正数之和不可能为 0
```

- 全正数数组：从 270ms → **0ms**；
- 另外两个可选剪枝：`nums[i]+nums[i+1]+nums[i+2] > 0: break`、
  `nums[i]+nums[-1]+nums[-2] < 0: continue`。

### 2. 去重写法：同时跳 vs 分别跳（实测快 10~13%）

"同时跳"（一个 while + and）比标准"分别跳"（两个 while）少一轮循环开销。

### 3. 缓存局部变量（实测快 2~6%）

`left, right = nums[j], nums[k]` 把数组元素缓存进局部变量（`LOAD_FAST` 比
`BINARY_SUBSCR` 快），对"被使用 2 次以上"的元素有净收益。

## ⭐ 关于"不敢排序"的顾虑（重要认知）

很多人怕排序的 O(n log n) 拖累复杂度——**要看排序是不是算法里最大的那一项**：

| 主算法复杂度 | 排序能否接受 |
|-------------|-------------|
| O(n²) 或更高 | ✅ 被淹没（本题排序只占 0.083%） |
| 题目要求 O(n) | ❌ 排序就是瓶颈（第 128 题） |

- 本题 n=3000：排序 ≈ 3.6 万次操作，主循环 ≈ 900 万次操作（**250 倍**）；
- 排序一石三鸟：双指针可用、去重变简单、剪枝可能。

## 本题考点

| 考点 | 内容 |
|------|------|
| 降维 | 三数之和 → 固定一个数 → 两数之和 |
| 排序 + 双指针 | 有序数组里 O(n) 找两数之和 |
| 去重 | 三处（i / j / k）；本质是"Δj=Δk=0 才重复" |
| 剪枝 | `nums[i] > 0: break` 等提前退出 |
| 对拍 | 用随机数据 + 参照实现抓潜伏 bug |
