# 55. 跳跃游戏 · 解析

## 题目简述

数组每个元素 = 从该位置最多能跳的步数，判断能否到达最后一个下标。

## 核心套路：贪心维护"最远可达位置 far"

**关键洞察**：不需要模拟每一跳，只需一路问"**到目前为止最远能到哪**"：

```python
def canJump(self, nums):
    far = 0
    for i, n in enumerate(nums):
        if i > far:              # 当前位置都到不了 → 前面有个坑
            return False
        far = max(far, i + n)    # 从位置 i 能跳到 i+n，更新最远
    return True
```

**两个关键点**：

1. **`if i > far: return False`**——捕捉"跳不过去的坑"。例 `[3,2,1,0,4]`：走到 i=4 时 far 只有 3（卡在 nums[3]=0），`4 > 3` → False；
2. **`far = max(far, i + n)`**——`i + n` 是"从 i 跳 n 步到达的位置"，一路取最大，最后看能否覆盖终点。

## 贪心骨架（与 121 完全同构）

| | 121 买卖股票 | 55 跳跃游戏 |
|--|-------------|------------|
| 维护的全局状态 | `min_price`（历史最低） | `far`（最远可达） |
| 每步更新 | `min_price = min(..., p)` | `far = max(..., i + nums[i])` |
| 失败条件 | 无（返回 0） | `i > far` |
| 复杂度 | O(n) | O(n) |

**贪心的灵魂**：每步只维护"目前为止的最优状态"，不回头、不枚举所有分支——因为**局部最优恰好能推出全局最优**。这是 55/121 共享的骨架，也是贪心算法的本质。

## 为什么不用 DP

55 的 DP 解法也存在（`dp[i] = 能否到达 i`，O(n²) 或 O(n·max_jump)），但贪心的"维护最远可达"O(n) 更优。**判断贪心是否适用**：如果"当前最优"能一路传递到终点（不依赖回头重算），贪心就是对的——55 的"最远可达"恰好有这个性质。

## 用户版绕在哪（可读性教训）

用户版用 `last_max`（值）+ `last_index`（下标）追踪，写 `last_max - i + last_index == 0` 判断"卡住"。本质和标准版一样（追踪最远可达），但**把单一概念拆成两个变量，再拼回魔法判断**——可读性崩塌。

**教训：状态变量越少越好。一个 `far` 能表达的，别用两个变量绕。**

## 复杂度

- 时间 **O(n)**；空间 **O(1)**。

## 考点

- 贪心"维护最远可达"
- 全局最优状态 + 一次扫描（121 同骨架）
- `i > far` 的"坑"判断

## 易错点

1. 忘 `if i > far` 判断 → 在坑处误判 True；
2. `far = max(far, i + nums[i])` 写成 `far = i + nums[i]`（没有 max，会回退）；
3. 空数组 / 单元素 `[0]` 应返回 True（已在起点即终点）；
4. 用 DP 的 O(n²) 暴力（能过但非最优）。
