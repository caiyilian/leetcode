# 543. 二叉树的直径 · 解析

## 题目简述

给你一棵二叉树的根节点，返回它的**直径**——任意两个节点之间最长路径上的**边数**（可能不经过根节点）。

示例：`[1,2,3,4,5]` → **3**（路径 4→2→1→3 经过 3 条边）。

## ⚡⚡ 核心模式：递归返回值 ≠ 题目答案（本题灵魂，务必吃透）

**fun 有两个职责，一个写在函数体里，一个写在 return 里：**

```python
def fun(self, root, max_list):
    if root:
        left_dep = self.fun(root.left, max_list)    # 先问左子树
        right_dep = self.fun(root.right, max_list)  # 再问右子树
        # 职责①（函数体）：两腿相加 = 经过当前节点的路径长度，更新全局答案
        max_list[0] = max(left_dep + right_dep, max_list[0])
        # 职责②（返回值）：单腿深度，交给父节点继续往上拼
        return max(left_dep, right_dep) + 1
    return 0
```

### 为什么"两腿相加"能覆盖所有直径？

任何直径路径都有**唯一一个最高点**（最靠近根、路径转折的地方），在最高点处：

```
路径长度 = 左子树最大深度 + 右子树最大深度
```

所以遍历每个节点，用「左深 + 右深」尝试更新答案——**全局最大值就是直径**（无论直径的顶在哪，都会被那个顶节点的计算覆盖）。

### 为什么返回值必须是"单腿深度"而不是"直径"？

**直径是横的（两腿）**，**深度是竖的（单腿）**。父节点要算自己那层的"左深/右深"，必须知道**从子节点往下还能伸多深**——所以每个子节点上交"单腿深度"。

> 如果 fun 返回直径，父节点就断了"往下伸几层"的信息——直径不一定经过父节点、方向也不对，没法继续拼接。
>
> **用两腿更新答案（给全局），用一条腿喂父节点（给上面）**——这就是 543 的全部设计。

### 全局变量为什么用 `max_list = [0]` 而不是普通 int？

Python 的 int 不可变，`max_list[0] = ...` 在**嵌套函数/递归中直接改外层变量**需要 `nonlocal`——用**长度为 1 的列表**绕开（list 可变，改元素不需要 nonlocal）。这是 Python 的惯用技巧，Interview 里也常见。

## 手动走一遍 [1,2,3,4,5]（感受两个职责的分工）

```
       1
      / \
     2   3
    / \
   4   5

4、5（叶）: 两腿 0+0，max=0，返回 1（单腿）
2        : 左1 右1，max=max(2,0)=2，返回 2
3（叶）  : 两腿 0+0，max=max(0,2)=2，返回 1
1        : 左2 右1，max=max(3,2)=3，返回 3（没人用了，根无父节点）
答案 = max_list[0] = 3 ✅
```

注意根节点返回的 3 被丢弃——**答案全程都在 max_list[0] 里**，return 只是给上面的材料。

## 复杂度

- 时间 **O(n)**：每个节点访问一次；
- 空间 **O(h)** 递归栈（最坏 O(n) 斜树）。

## 考点

- **"返回值传材料、全局装答案"模式**（124 最大路径和同款，后者是二叉树困难题的明星）
- 后序遍历顺序（先问完左右再算自己——两腿必须先都拿到）
- Python 可变对象绕开 nonlocal（列表装全局）
- 直径 ≠ 经过根的路径（`[1,2,3]`：直径是 1+1=2 条边经过根；但有些树直径不经过根，如 `[1,2,3,4,5,6]` 形状）

## 易错点

1. **返回值写成直径而不是深度**——最经典错误（拿不到单腿信息，父节点算不出）；
2. 忘记更新 max_list（只 return 不更新——答案永远是 0）；
3. 空树返回 0、单节点返回 0（直径 = 边数，单节点无边）；
4. 直径是**边数**不是节点数（`[1,2,3]` 直径 2，不是 3）。

## 与 104 的关系

104 返回的就是"单腿深度"（`1 + max(左右)`）——543 在 104 的基础上多加了"用两腿更新全局答案"这一件事。**104 是 543 的子问题，543 是 124 的预演**——一条递进链。
