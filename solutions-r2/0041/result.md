## 本地死循环坑（用户标注，已详解）

用户在本地曾用 `nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]` 直接交换 → 死循环。

**根因：Python 元组交换的求值顺序**——右侧先算，左侧下标**从左到右依次求值**：

```
nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]
① 右侧：R1 = nums[nums[i]-1], R2 = nums[i]（都是旧值）
② nums[i] = R1（i 未变，正常）
③ nums[nums[i]-1] = R2 ← 此时 nums[i] 已是 R1！nums[i]-1 是"新"下标 → 写错位置
```

左侧第二个下标里的 `nums[i]` 用了**第一步赋值后的新值** → 下标被污染 → 归位失败 → 死循环。

**解法：先冻结 `target_index = nums[i] - 1` 再交换**（用户已自行修复）。

**通用教训**：Python 单行交换中，若左侧下标依赖同一列表的其他下标，**必须先把下标冻结成变量**再交换（C/Java 的三变量交换无此问题）。
