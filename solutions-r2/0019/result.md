## WA → AC 复盘（本次重点）

**WA 版核心 bug：删头节点时返回空链表**

```python
if prev is None:
    return prev    # ❌ prev 是 None，return 直接返回 None → 整条链被删
```

当 `n == len(链表)`（删的是头节点）时：fast 先走 n 步到 None，`while p_fast` 一次都不进，`prev` 保持初始 `None`，`p_slow` 还是 head。此时想删的是**头节点**，正确应返回 `head.next`。WA 版却 `return prev`（= None），把整条链删了（复现：`[1,2,3,4,5]` n=5 → `[]`，应为 `[2,3,4,5]`）。

**为什么一刷没踩到**：一刷时写了 dummy 哨兵，`prev` 从 dummy 起步，删头节点时 `prev = dummy`，`dummy.next = p_slow.next` 天然正确。二刷 v1 想精简掉 dummy，结果把"prev 永远非空"这个保障丢了。

**修复（v2）**：把 dummy 加回来，`prev` 从 dummy 起步：

```python
dummy = ListNode(0)
dummy.next = head
prev = dummy          # ★ prev 永远非 None：删头时就是 dummy
...
prev.next = p_slow.next
return dummy.next     # 即使删头，dummy.next 也是新头
```

**教训**：**"删链表节点"类题目（19/237/203 等），用 dummy 哨兵让前驱永不落空，是消除头节点特判的通用手段**——你 v1 精简时恰好在"头节点永远有前驱"这个假设上翻车，一刷写过 dummy 证明你已经会，二刷只是简化过头。
