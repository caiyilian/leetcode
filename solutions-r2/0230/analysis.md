# 230. 二叉搜索树中第 K 小的元素 · 解析（二刷）

## 一、核心思路：BST 中序 = 升序

**BST 最重要的性质**：中序遍历（左中右）的结果是**升序数组**（98 验证 BST 就用它）。

```
    3          中序 [1,2,3,4]
   / \        第 k 小 = 中序第 k 个
  1   4
   \
    2
```

所以"第 k 小" = **中序遍历数到第 k 个节点**。O(n) 遍历 → 数到 k 停。

## 二、代码（用户 AC 版）：计数 + 答案分离

```python
result = [k, 0]           # result[0]=剩余计数, result[1]=答案
def fun(root):
    if root:
        fun(root.left)    # 中序：先左
        result[0] -= 1
        if result[0] == 0:        # 数到第 k 个
            result[1] = root.val  # 存答案（独立位置）
            return                # 剪枝：不再遍历右子树
        fun(root.right)
fun(root)
return result[1]
```

两个技巧：
- **计数剪枝**：找到第 k 个立即 `return`，不再走下去（中序找到即答案）；
- **闭包用 list 包一层**（`result[0]`/`result[1]`）：递归里改外层变量，避免 `nonlocal` 声明。

## 三、⚡ WA 坑：过程量 vs 结果量别共用一个变量

WA 版用一个 `result[0]` 既当计数又当答案，找到后 `result[0] = root.val` 覆盖计数——但**回溯时祖先层还会 `result[0] -= 1`**，把刚存的答案改坏。

**为什么答案会变**：`return` 只让"找到的那一层"提前退出；它的**祖先**在 `fun(root.left)` 返回后，还会接着执行 `result[0] -= 1` 和 `fun(root.right)`——计数必须继续递减（虽然不再需要），而答案被当计数继续减。

**原则**：**过程量（计数/指针）和结果量（答案）永远分开存**。这也是"闭包里多状态"的通用教训（类似 138 的 hash_map 不要复用）。

## 四、进阶：如果能改树节点，维护子树大小 O(log n)

如果允许给每个节点加 `size` 字段（左子树节点数），可以二分式查找（比较 k 与左子树大小）→ **O(log n)**。但通常面试题不要求（要改数据结构），中序 O(n) 就够。

## 五、复杂度

- 时间：O(h+k)——h 到最左，k 数到答案（最坏 O(n)）
- 空间：O(h)（递归栈）

## 六、一刷 vs 二刷

- 一刷（9-15）：中序+计数 → v2 剪枝（AC ×3）；
- 二刷（10-24）：v1 计数复用 WA → v2 分离 AC——**思路标准，坑在状态管理**。

## 八、一句话记住

> **BST 第 k 小 = 中序遍历数到 k：计数递减到 0 存答案并剪枝（return）；计数器与答案必须两个变量，混用会被回溯减坏。**
