## ⚡ WA → AC 复盘（计数变量被污染）

**WA 版**：

```python
result = [k]          # 一个变量既当计数又当答案
...
result[0] -= 1
if result[0] == 0:
    result[0] = root.val   # ★ 找到答案，但把计数覆盖了
    return
fun(root.right)
```

**根因**：`result[0] = root.val` 把计数覆盖成答案后，**回溯到父/祖先层还会继续对 result[0] 做 `-= 1`**（因为 `return` 只在"找到答案"的那一层生效，上层的 `fun(root.right)` 没被跳过），把刚存的答案又减掉/改坏。

**实测反例**：`vals=[-98,...,93] k=9` 应返回 31，WA 返回 9（计数残留）；`[34,77] k=2` 应返回 77，WA 返回 2。

**修复（AC 版，用户已做对）**：计数和答案分离：

```python
result = [k, 0]       # result[0]=剩余计数, result[1]=答案
...
result[0] -= 1
if result[0] == 0:
    result[1] = root.val   # 答案存独立位置，计数不会再碰它
    return
```

**教训**：**闭包里多个"状态"别共用一个变量**——计数是"过程量"（会被反复修改），答案是"结果量"（只能写一次），混用必出事。一刷记忆里 230 的 v2 剪枝版就是分离的，这次 v1 踩了没分离的坑。
