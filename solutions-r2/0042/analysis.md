# 42. 接雨水 · 二刷解析

## 题目回顾

柱状图（高度数组），计算下雨后能接多少水。核心：**每一格的水 = min(左最高, 右最高) - 自身高度**（正值才算）。

## 三种解法（一刷双指针 / 二刷单调栈 / 动态规划）

| 解法 | 思路 | 时间 | 空间 |
|------|------|------|------|
| **单调栈（二刷）** | 遇高弹栈结算洼地 | O(n) | O(n) |
| **双指针（一刷定稿）** | 左右各维护已见最高，矮边结算 | O(n) | **O(1)** |
| 动态规划（预计算） | 左右 max 数组，逐格取 min-max | O(n) | O(n) |

**双指针空间最优**；**单调栈是通用模板**（84/739 同款）。面试两种都会写最有优势。

## 单调栈细节（二刷重点）

```
height = [0,1,0,2,1,0,1,3,2,1,2,1]
遍历到 i=3 (2)：栈=[0,1,2]（递减），2 > height[2]=0 → 弹 2 结算：
  mid=2（洼地 0），栈顶变 1（高1）→ 宽 = 3-1-1 = 1，高 = min(2,1)-0 = 1 → +1
遍历到 i=7 (3)：栈=[3,4,5,6]，3 > 1 → 弹 6：宽 = 7-5-1 = 1，高 = min(3,1)-0 = 1 → +1
  3 > 1 → 弹 5：宽 = 7-4-1 = 2，高 = min(3,1)-1 = 0 → +0
  3 > 2 → 弹 4：宽 = 7-3-1 = 3，高 = min(3,2)-1 = 1 → +3
  ...
总计 6 ✓
```

**弹出即结算**：每次弹出 mid 时，它左右两侧的"墙"就是新栈顶（左墙）和当前 i（右墙），两者取低再减掉 mid 自身高度 = 这格能存的水。

## 疑问 1 详解：为什么 `if not stack: break` 不能换成 while 条件

```python
while stack and height[i] > height[stack[-1]]:   # 条件：只在回到 body 开头时求值
    mid = stack.pop()                            # 空栈发生在 body 中间（这之后）
    if not stack: break                          # ★ 必须在这里判断
    w = i - stack[-1] - 1                        # 之后要用 stack[-1]（左墙），空栈会 IndexError
```

- **while 条件的求值时机**：只在"进入循环前"和"每轮 body 执行完回到开头"时检查；
- **空栈产生时机**：`pop()` 在 body **中间**执行后才可能空——这时 while 条件"还没轮到下次检查"，但第 4 行已经要碰 `stack[-1]` 了 → 必须在 body 里显式处理。
- 等价写法：`if stack:` 守卫（有左墙才结算），语义与 `break` 相同，更顺眼。

**通用结论**：任何"pop 之后还要用栈顶"的单调栈题（84、739、42）都需要这个空栈判断，这是单调栈的标准形态。

## 疑问 2 详解：`[0]+height+[0]` 对 42 无用（84 专属）

| | 84 最大矩形 | 42 接雨水 |
|--|-----------|----------|
| 弹栈触发 | 遇**更矮**的柱子 | 遇**更高**的柱子 |
| 遍历完栈剩 | 单调递增柱**欠结算** | 递减柱**本就无水** |
| 尾哨兵 `+[0]` | **必需**（0 最矮 → 强制弹空清栈） | **无用**（0 永远不高于栈顶，永不触发弹出） |
| 头哨兵 `[0]+` | 可选（预处理） | 冗余（`stack=[0]` 已预置下标 0） |

**用户的直觉正确**：`[0]+height+[0]` 是 84 的"尾 0 强制清栈"专用技巧，42 不需要（你注释掉它也 AC 了，就是证据）。42 只需要 `stack = [0]`（初始左墙）+ `range(1, length)`（从下标 1 遍历）。
