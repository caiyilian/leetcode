# 322. 零钱兑换 · 解析（二刷）

## 一、题目

- 中文：零钱兑换
- English：Coin Change
- 难度：中等（完全背包：每种硬币数量无限）

## 二、核心思路：完全背包一维 DP

**问题**：用最少的硬币凑出 amount（每种硬币无限用），凑不出返回 -1。

**状态定义**：
```
dp[i] = 凑出金额 i 所需的最少硬币数
dp[0] = 0
dp[i] = min(dp[i - j] + 1)  对每个硬币面值 j ≤ i
答案 = dp[amount]（inf 表示凑不出 → -1）
```

**为什么是"完全背包"**：内层枚举硬币时**不限制使用次数**（一维正序遍历，同一个硬币可以反复用）——和 279 完全平方数同源（每个平方数也是无限用）。

**两层循环顺序**：外层金额 i、内层硬币 j。这样 dp[i - j] 一定已经在本次外层算过（i-j < i），正向顺序天然满足"同一个硬币可重复选"。

## 三、代码（用户 AC 版）

```python
coins.sort()
dp = [float('inf')] * (amount + 1)
dp[0] = 0
for i in range(amount + 1):
    for j in coins:
        if j > i:
            break              # ⚡ 排序 + 提前剪枝（也避免负下标）
        dp[i] = min(1 + dp[i - j], dp[i])
return dp[amount] if isinf(dp[amount]) is False else -1
```

## 四、⚡ 二刷 RE 复盘

**坑**：内层 `dp[i-j]` 在 `j > i` 时下标为负 → **IndexError**。
**两类解法**：

| 方式 | 写法 |
|------|------|
| 排序 + break（用户采用） | `coins.sort()` 后 `if j > i: break` |
| 不排序遍历判断 | `if j <= i:` 才更新（少排序但每轮全扫） |

排序 break 更优：不仅防越界，还把无效硬币提前跳掉（剪枝）。**这个坑和 279 完全平方数 2 刷时的"内层上界"是同一类——内层枚举范围必须限制在有效下标内**。

## 五、复杂度

- 时间：O(amount × n)（n = 硬币种类数）
- 空间：O(amount)

## 六、关联题目：背包家族

| 题 | 类型 | 区别 |
|----|------|------|
| **322 零钱兑换** | 完全背包·最少个数 | 求 min 个数，inf 表示无解 |
| **279 完全平方数** | 完全背包·最少个数 | 硬币 = 平方数（无限用），同模板 |
| **518 零钱兑换 II** | 完全背包·方案数 | 求方案总数（累加，注意去重顺序）|
| **416 分割等和子集** | 0-1 背包 | 每个数只能用一次 |

**识别信号**："每种物品无限用 + 求最少/方案数"→ 完全背包一维 DP；外层物品/金额顺序决定是"组合"还是"排列"。

## 七、一句话记住

> **322 = 完全背包：dp[i]=min(dp[i-j]+1)，外层金额内层硬币（无限复用），dp[0]=0，inf 兜底返回 -1；⚡ 内层枚举前先排序、j>i 即 break——防负下标又剪枝。**
