# 79. 单词搜索 · 解析（二刷）

## 一、核心思路：网格 DFS 回溯 + 原地标记

**问题**：board 网格中找 word（相邻格上下左右连接，**同一格不能重复用**）。

**模板**（和 51 N皇后/46 全排列同源，只是"used"变成"棋盘标记"）：

```
匹配当前格 → 标记已用 → 四方向递归 → 恢复标记
```

```python
def fun(index, i, j):
    # ① 越界 / 字符不匹配 → False
    if 越界 or board[i][j] != word[index]: return False
    # ② 匹配到最后一位 → True
    if index == length - 1: return True
    # ③ 标记 + 四方向 + 恢复
    c = board[i][j]; board[i][j] = '0'
    if fun(index+1, 上/下/左/右): return True
    board[i][j] = c          # 恢复
    return False
```

外层：遍历所有格，遇到 `board[i][j] == word[0]` 就以它为起点 DFS。

## 二、⚡ 两个必背细节（本次 WA 的教训）

**① 标记/恢复必须成对，且恢复别存错字符**：
```python
c = board[i][j]    # ★ 备份（下标别写错！v1 写成 board[i][i] 酿成 WA）
board[i][j] = '0'  # 标记已用（防回头——同一格不能重复用）
...四方向...
board[i][j] = c    # 恢复
```

**② 成功判定放"当前格匹配到最后一位"（`index == length-1`），而不是"深度+1 后再判"（`index == length`）**：
- `index == length` 版：在递归入口判成功 → 找到路径后**提前 return**，跳过这层的恢复 → 棋盘污染；
- `index == length-1` 版：匹配当前格就是成功，**不需要再递归** → 不存在提前返回跳过恢复的问题。

**为什么污染危险**：棋盘的 `'0'` 标记如果没恢复，后续对**同一块棋盘**的搜索（本起点其他路径、或其他起点）会把这个格当"已用"而漏解。本题找到即整体返回所以没炸，但刷 212 单词搜索 II（要返回多个单词）时**棋盘恢复错误是致命 bug**。

## 三、复杂度

- 时间：O(m×n×4^L)（最坏每个起点都全展开；剪枝后一般远小于）
- 空间：O(L)（递归栈）

## 四、一刷 vs 二刷

- 一刷（9-16）：WA→RE→AC ×2；
- 二刷（10-29）：WA×2（下标手误 + 成功判定位置）→ AC。**骨架对，细节是关键**。
