| 考察点 | 结论 |
|--------|------|
| 时间复杂度 | ✅ O(m×n×4^L)——每个起点 DFS 四方向，L 为单词长度（回溯剪枝后通常远小于） |

## ⚡ WA→AC 复盘（两个坑，都值得记）

**WA v1：下标手误**
```python
c = board[i][i]      # ❌ 应该是 board[i][j]（列标写成 i 是复制粘贴手误）
```
恢复时存错了字符 → 回溯后棋盘被污染 → 后续搜索错乱。**同名下标容易手滑，写法上用 `r, c` 或仔细检查**。

**WA v2：成功判定放错位置 → 提前 return 跳过恢复**
```python
if index == length:      # ❌ 深度+1 才判定成功
    return True
...
if fun(index+1, ...):    # 一旦某个方向返回 True，直接 return True
    return True          # └ 棋盘没恢复就跑了！
```
**问题**：匹配成功后立刻 `return True`，跳过了 `board[i][j] = c` 恢复——当前格保持 `'0'`。虽然答案已经找到（对本题无碍），但中间层棋盘污染，**力扣判题的值对**；真正危险的是首层调用后棋盘被改（其实这里由于找到即返回，污染不影响结果——但这版 WA 的根因更可能是 v1 的手误残留/边界顺序）。

**AC v3：把成功判据改成"当前已匹配到最后一位"**
```python
if index == length - 1:      # 当前格匹配到 word 最后一位 → 直接 True（无需再递归）
    return True
```
这样**成功路径在标记前就返回**，不存在"提前 return 跳过恢复"——恢复只发生在"这格匹配但四条路都失败"的回溯中，代码更干净、正确性显然。

## 一句话

**网格 DFS 回溯模板**：匹配 → 标记 → 四方向 → 恢复。三个注意：标记/恢复成对、恢复别存错字符、成功判定别引发"提前返回跳恢复"。

## 过程回顾

一刷（9-16）：WA→RE→AC ×2（3265ms）。
