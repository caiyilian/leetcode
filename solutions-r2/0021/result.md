## 是否最优解？✅ 是

| 考察点 | 结论 |
|--------|------|
| 时间复杂度 | ✅ O(n+m)——每个节点恰好被接一次 |
| 空间复杂度 | ✅ O(1)——哨兵节点 1 个 + 指针常数个（不算返回链表的节点） |
| 正确性 | ✅ 5 个手工用例（等长/一空/全空/全小在前/全大在后）+ 3 万组随机对拍 0 不一致 |
| 进阶要求 | ✅ 满足力扣"O(1) 空间" |

## 解法亮点：二刷换了个打法（哨兵归并，一刷是交换头）

- 一刷：交换头 + 插入法，不变量 `p1.val ≤ p2.val`，无 dummy；
- 二刷：**哨兵 + while 循环逐个接**——更贴近标准写法，且**通用性更强**（23 题合并 K 个升序链表的每一轮 merge 就是它）。

细节对比：
- 循环条件用 `list1 or list2`（任一非空继续），比标准写法 `while list1 and list2` + 尾部一次性接剩余 更"显式"——每次只接一个节点，逻辑直白；
- 空链表天然安全：list1 为 None 时直接接整个 list2，无需特判。
