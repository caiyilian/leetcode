# 105. 从前序与中序遍历序列构造二叉树 · 解析（二刷）

## 一、核心思路：前序定根，中序分界

两个关键观察（**母题核心，106/889 都用它**）：

1. **前序遍历**：`根 → 左子树 → 右子树`，所以 `preorder[l1]` 永远是当前子树的根；
2. **中序遍历**：`左子树 → 根 → 右子树`，所以根在中序的位置，左边全是左子树、右边全是右子树。

```
preorder = [3, 9, 20, 15, 7]      inorder = [9, 3, 15, 20, 7]
            ↑根=3                            ↑根=3
           左子:[9]       右子:[20,15,7]     左子:[9]  右子:[15,20,7]
```

**只要知道根在中序的位置，就能算出左子树有几个节点**，进而把前序也切成左右两半——递归下去就建出整棵树。

## 二、四边界递归（用户 AC 版）

```python
def fun(l1, r1, l2, r2):        # 当前子树：前序 [l1,r1)、中序 [l2,r2)
    root_val = preorder[l1]                    # 前序第一个 = 根
    idx = inorder.index(root_val)              # 根在中序的位置
    root = TreeNode(root_val)
    left_num = idx - l2                        # 左子树节点数（中序 l2..idx）
    right_num = r2 - idx - 1                   # 右子树节点数
    if left_num:
        root.left = fun(l1+1, l1+1+left_num, l2, idx)     # 左子树区间
    if right_num:
        root.right = fun(l1+1+left_num, r1, idx+1, r2)     # 右子树区间
    return root
```

四个边界分别圈定两棵子树在两数组中的范围——**左子树区间全由 left_num 推导**，这是本题的巧点。

## 三、优化：index_dict 预哈希（O(n²) → O(n)）

`inorder.index(root_val)` 每层递归都全数组扫描一次 → 最坏 O(n²)。**值→下标预哈希一次**，找根变 O(1)：

```python
index_dict = {v: i for i, v in enumerate(inorder)}
...
idx = index_dict[root_val]      # O(1)
```

另外优化版把 `if left_num` 换成 `if l1 >= r1: return None`（空区间判定）——更通用，还顺带解决空输入崩溃（本题无此输入）。

## 四、复杂度

| | 裸 index（用户版） | 预哈希（优化版） |
|---|---|---|
| 时间 | 最坏 O(n²) | **O(n)** |
| 空间 | O(n) | O(n) |

力扣规模 ≤3000，两版都秒过；面试说得出预哈希优化 → 加分项。

## 五、一刷 vs 二刷

- 一刷（9-15）：四边界递归 + index_dict 预哈希，AC ×2；
- 二刷（10-24）：独立写出四边界递归一次 AC，裸 index 退化点已识别并补齐优化版——**思路完全掌握，只剩"查找预哈希"这个常数优化**。
