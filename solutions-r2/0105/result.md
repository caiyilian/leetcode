## 是否最优解？⚠️ 思路最优，性能可优化一处

| 考察点 | 结论 |
|--------|------|
| 时间复杂度 | ⚠️ 最坏 O(n²)——`inorder.index()` 每次 O(n) 找根，每层递归都全数组扫描 |
| 空间复杂度 | ✅ O(n)——递归栈 O(h) + 每层建节点 |
| 正确性 | ✅ 3 个手工用例 + **力扣约束范围内（n>=1）2 万组随机树对拍**（vs 预哈希参照版）0 不一致 |
| 思路 | ✅ 前序定根、中序分界、四边界递归 = 教科书标准 |

**小优化**：一刷用的 `index_dict = {v:i}` 预哈希版，找根 O(1) → 总 O(n)。本次用户版用 `inorder.index()` 裸查找退化到最坏 O(n²)。但力扣数据规模小（≤3000），35ms 无感，两版都 AC。**归档附上预哈希优化版**，面试说得出"可以预哈希到 O(n)"就是加分。

**边界提醒**：空输入（`preorder=[]`）会 `preorder[0]` 越界崩溃——但力扣约束 `1 <= preorder.length`，永不出现，无影响。

## 思路复盘

- **前序定根**：`preorder[l1]` 永远当前子树的根（前序 = 根→左→右）；
- **中序分界**：根在中序的位置 `index_root_inorder`，左边 `[l2, idx)` 是左子树，右边 `(idx, r2]` 是右子树；
- **左子树大小** `left_num = idx - l2` → 反推左子树在前序的区间 `[l1+1, l1+1+left_num)`；
- **四边界递归**：`(l1,r1,l2,r2)` 圈定子树在两数组的位置，`if left_num / if right_num` 决定是否建子树。
