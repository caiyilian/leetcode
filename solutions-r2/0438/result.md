## 失败提交记录（RE 754358445）

**唯一差别：缺 `if len_s < len_p: return []` 守卫**

```python
# RE：没有 s 比 p 短的守卫
for i in range(len_p):
    counts[ord(p[i])-97] += 1
    now[ord(s[i])-97] += 1      # ❌ p 比 s 长时 s[i] 越界 → IndexError

# AC：加一行
if len_s < len_p:
    return []                   # ✅ s 不够长，不可能有异位词
```

**教训**：初始化循环用 `len_p` 遍历 `s`，当 `p > s` 时下标越界。"**循环用哪个长度、访问哪个数组**"的边界是滑动窗口题的高频 RE 源。AC 版加上了，一刷也踩过类似的。

## 解法一句话

**定长滑动窗口 + 26 计数数组**：窗口长度 = len(p)，先装第一个窗口；每步右进 +1、左出 -1（增量更新），窗口计数 == p 计数即命中。

- 时间复杂度：**O(len_s + len_p)**（每字符进出一次；26 位比较是常数）
- 空间复杂度：**O(1)**（两个 26 长度数组）

## 验证

- **对拍**：5000 组随机（小字母表制造命中），与暴力 Counter 对照，**0 不一致** ✅
- 样例 `cbaebabacd/abc→[0,6]`、`abab/ab→[0,1,2]`、`aaaaaaaaaa/aa→[0..8]`、`a/ab→[]` 全对

## 是否最优解

**是，标准最优解**：O(n) 时间（下界）+ O(1) 空间。每次比较整个 26 数组已是常数开销（O(26n) 与 O(n) 同阶）；若想再抠可用 `diff` 计数差异字符，但非必须。
