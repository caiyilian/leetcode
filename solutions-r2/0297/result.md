## ⚡ RF → AC 复盘：下标建树 vs 队列消费

**RF 版（20:44）**：serialize 用 BFS 层序（deque）没问题，**deserialize 用下标公式建树**：

```python
for i in range(int(2**(log2(length+1)-1) - 1)):   # 想算"非叶子层数"，复杂又易错
    data[i].left = data[2*i+1]
    data[i].right = data[2*i+2]
```

**问题**：① 层序数组不是"满二叉树"，`2*i+1`/`2*i+2` 在 None 位置会**越界/漏连**；② `log2` 层数公式对任意形状树不对。RF = 运行时结果错误（越界等），RE = 运行异常——都源于下标魔法。

**AC 版（21:26）**：反序列化改用**队列消费**——队列存"等着接孩子的父节点"，`i` 指针每次消费左/右两个值：

```python
while q:
    node = q.popleft()
    i += 1; left = data[i]; if left != 'None': node.left = TreeNode(left); q.append(...)
    i += 1; right = data[i]; ...
```

**为什么稳**：数据从左往右读一遍，每个父节点恰好消费 2 个值 → **天然对应层序结构，不会越界**；None 不建节点不入队。

## 过程回顾

一刷（9-21）：DFS 前序 + N, 哨兵（AC ×2）。
二刷（10-25）：BFS 层序 serialize + 下标建树 RF/RE → **队列消费 AC**——**"弹出父、消费左右"这个心法 get 了**（比下标公式直观且不易错）。

## ✅ 回答用户疑问："不允许用双向队列？"

**不是**。`collections.deque` 标准库随便用，RF 的锅是**反序列化的下标魔法算错**，不是 deque。换队列消费版后一次 AC。
