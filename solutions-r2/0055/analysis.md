# 55. 跳跃游戏 · 解析（二刷）

## 一、核心思路：贪心——维护最远可达距离 far

**问题**：从下标 0 出发，`nums[i]` 是最多跳多远，判断能否到最后一个下标。

**贪心关键**：**只要记录"当前能到达的最远位置"**（far），遍历每个位置：
- 若位置 i 可达（`i <= far`），则从 i 出发最远能到 `i + nums[i]`，`far = max(far, i + nums[i])`；
- 若某个位置 `i > far`（到不了）→ 后面全到不了 → False；
- 全程 `far >= 最后一个下标` → True。

**为什么不用记录路径**：可达性只取决于"有没有位置能把我送到更远"，far 单调不降地覆盖所有可达位置——**能到达终点 ⟺ 遍历中没有位置超出 far**。

## 二、代码（用户 AC 版 + 标准版）

```python
# 用户版：range(length-1) + far==i 判 0
for i in range(length - 1):          # ⚡ 只查末尾之前
    if far == i and nums[i] == 0:    # 当前位置过不去
        return False
    far = max(far, i + nums[i])
return True

# 标准版：i > far 判死路（推荐，语义最清晰）
for i in range(len(nums)):
    if i > far: return False         # 到不了 i → 死路
    far = max(far, i + nums[i])
return True
```

## 三、⚡ 核心坑：末尾元素（WA×2 复盘）

**坑**：末尾元素是 0 **不是死路**——题目要求"到达最后一个下标"，不需要再从末尾跳出去。`[2,0,0]`、`[1,0]` 都能到达终点。

- 用户 v1/v2 遍历全部下标 → 末尾 0 且 far==末尾 → 误判 False；
- **v3 用 `range(length-1)`**：末尾不参与"能否越过"检查；
- 标准版 `i > far` 天然正确：末尾只要 i<=far 就说明能到达，不会因为它自身是 0 而报错。

**一句话**：**判断条件只看"能否到达"，不从末尾再出发**——所以末尾的 nums 值无所谓。

## 四、复杂度

- 时间：O(n)
- 空间：O(1)

## 五、一刷 vs 二刷

- 一刷（9-18）：贪心 AC ×2；
- 二刷（10-31）：WA×2 → AC——"末尾 0 不算死路"这个坑今天踩实了，**标准写法 `i > far` 是防坑首选**。
