## ⚡ WA→AC 复盘：末尾 0 的误判（写这题的经典坑）

**v1/v2 的错误**：遍历 `range(length)` 全部下标，当**最后一个元素是 0 且 far 恰好到末尾**时，会误判 False。

**为什么是错的**：题目只要"能到达最后一个下标"就赢了——**末尾元素本身是不是 0 无所谓**（不用从它再跳出去）。比如 `[2,0,0]`：far 到 2（末尾），最后一步已经在终点了，v1 却因为 `nums[2]==0 and far==2` 判 False。

**v3 修复**：`range(length - 1)` 只检查前 length-1 个位置（"能否越过这些位置"），末尾天然不用检查：
```python
for i in range(length - 1):          # 只查 length-1 个（末尾 0 不算死路）
    if far == i and nums[i] == 0:    # 当前位置无法越过 → 死路
        return False
    far = max(far, i + nums[i])
return True
```

**更通用的写法**（标准答案，语义更清晰）：遍历全部，用 `if i > far: return False`（到不了当前位置即死路）——末尾同样被"到达即胜利"覆盖：
```python
far = 0
for i in range(len(nums)):
    if i > far: return False     # 到不了 i
    far = max(far, i + nums[i])
return True
```

## 贪婪为什么对

**只维护"最远可达 far"**：只要能到 i，且 i 能跳到 i+nums[i]，那从 i 出发能覆盖 [i, i+nums[i]] —— 不需要记录具体路径，**全局最远可达单调不降**，扫一遍即可判断是否能到终点。
