# 11. 盛最多水的容器 · 二刷解析

## 题目回顾

垂直线高度数组 `height`，任选两条线组成容器，求能盛水的最大容量。容量 = 两线距离 × 两线中较矮的高度。

## 核心思路：双指针两端收缩（贪心）

**一句话**：两个指针从最宽（首尾）开始，**每次都移动较矮的那根**——矮边决定水位，动它才有机会让容量变大；动高边只会让距离变小、水位不变，不可能变优。

```python
left, right = 0, len(height) - 1
while left < right:
    if height[left] < height[right]:   # 左矮
        now = (right - left) * height[left]
        left += 1                       # 动左（矮）
    else:                               # 右矮（或相等）
        now = (right - left) * height[right]
        right -= 1                      # 动右（矮）
    max_storage = max(max_storage, now)
```

## 为什么"矮的动"是正确的（贪心安全性证明）

以"左矮、动右"为例，说明为什么可以放心跳过"动右"的所有状态：

```
h[left] < h[right]，当前容量 = (right-left) × h[left]
如果不动 left 而把 right 往左移：距离变小，而高度仍被 h[left] 限制
→ 新容量 = (更小距离) × h[left]（或更低） < 当前容量
→ 以 left 为左边界的任何后续状态都不可能是全局最优
→ 跳过右指针安全，唯一可能变优的方向是移动矮边 left
```

**这就是贪心能保证最优的原因**：每一步被跳过的状态都"不可能更优"，所以扫过的状态里必含最优解。双指针从最宽开始收缩，每个元素最多被访问一次 → **O(n)**。

## 三个细节（二刷重点）

1. **相等时动哪边**：`h[left] == h[right]` 动哪边都等价（该区间内两边都不可能再贡献更优），你的 else 动右没问题。
2. **容量公式别记错**：`(right - left) × 矮边高度`——是**下标差 × 矮边**，不是高度差。
3. **为什么不是"动高边"**：动高边 = 距离变小 + 水位不变/变小 → 容量必不增，纯亏。**只有矮边动了，才有机会换更高的边**。

## 一刷 vs 二刷

一刷：TLE（暴力 O(n²)）→ WA ×2 → 4 次迭代才定稿双指针（记忆里是"用户 4 次迭代定稿为左右双指针"）。
二刷：**一次写出 O(n) 双指针 + 注释还点出"低的那个动"**——核心洞察已内化，从"踩坑摸索"变成"直接秒写"。
