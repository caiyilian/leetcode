## 解法核心：只比较 nums[mid] 和 nums[right]

旋转数组被"断点"切成两段：**大段（值都大）+ 小段（含最小值）**。两个分支：

```python
while left < right:
    mid = (left + right) // 2
    if nums[mid] > nums[right]:   # mid 在大段 → 最小值在右半（mid 右边必有更小的 right）
        left = mid + 1            #   mid 可放心排除
    else:                          # mid 在小段 → 最小值可能是 mid 自己
        right = mid               # ★ 必须保留 mid（别写 mid-1，会弄丢候选最小值！）
return nums[left]
```

**为什么跟 right 比而不是 left**：`nums[mid] > nums[right]` 成立 ⟺ mid 在大段（大段最小值 > 小段最大值，如果 mid 在大段，则右边要么还在大段、要么进入小段，必然有 ≤ nums[right] < nums[mid] 的更小值）。跟 left 比还要判断断点位置，麻烦且易错——**统一跟 right 比是最短路径**。

## ⚡ 循环边界（最容易炸的地方）

- `while left < right`（不是 `<=`）——否则单元素/收敛时可能死循环；
- `right = mid` 保留候选（`mid-1` 会跳过最小值），`left = mid + 1` 排除确定不是的；
- 退出时 `left == right` → `nums[left]` 即最小值。
