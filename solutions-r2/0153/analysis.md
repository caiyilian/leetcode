# 153. 寻找旋转排序数组中的最小值 · 解析（二刷）

## 一、核心思路：二分找断点（大段 / 小段）

**问题**：无重复的旋转排序数组，找最小值。

**关键观察**：旋转数组被"断点"切成两段——
- **大段**（如 `4,5,6,7`）：所有值都大；
- **小段**（如 `0,1,2`）：**最小值在它的开头**（即断点）。

只要二分时判断 mid 落在大段还是小段，就能不断逼近断点：

```
[4,5,6,7,0,1,2]   mid=3 → 7
  7 > 2（nums[right]）→ mid 在大段 → 最小在右 → left=mid+1
  [0,1,2] mid=1 → 1 ≤ 2 → mid 在小段 → 保留 mid → right=mid
  [0,1]   mid=0 → 0 ≤ 1 → right=mid → left==right → 返回 nums[left]=0 ✅
```

## 二、代码（用户 AC 版，就是标准版）

```python
left, right = 0, len(nums) - 1
while left < right:                  # ⚡ 不是 <=
    mid = (left + right) // 2
    if nums[mid] > nums[right]:      # mid 在大段 → 最小值必在右半
        left = mid + 1               #   mid 可排除
    else:                             # mid 在小段 → 最小值可能是 mid 自己
        right = mid                  # ★ 必须保留 mid（不能 mid-1）
return nums[left]
```

## 三、三个必记要点（⚡ 全是坑点）

1. **跟 `nums[right]` 比**：`nums[mid] > nums[right]` ⟺ mid 在大段（更小值必在右边）；跟 left 比要处理断点在左/右两种情况，麻烦易错——**统一跟 right 比**；
2. **`right = mid` 保留候选**：小段里 mid 可能就是最小值，`mid-1` 会把它跳过（一刷 WA 的根因）；
3. **`while left < right`**：收敛到 left==right 即答案，用 `<=` 在边界会卡死。

## 四、复杂度

- 时间：O(logn)
- 空间：O(1)

## 五、一刷 vs 二刷

- 一刷（9-17）：WA 1 次 → AC ×2（当时也是 `mid-1` 或边界问题）；
- 二刷（10-30）：卡住后按提示"只比 mid 与 right + right 保留 mid"一次 AC——**"大段/小段"模型建立**，下次写旋转数组都不会再绕。
