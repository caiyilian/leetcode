# 76. 最小覆盖子串 · 解析（二刷）

## 一、核心思路：可变滑动窗口（右扩→左缩）

```
右指针 right 不断右移，把字符纳入窗口
  直到窗口"完全覆盖" t（每个字符出现次数 ≥ t 的需求）
然后左指针 left 右移收缩，缩到"刚好不覆盖"为止
  收缩前的那一刻 = 一个候选答案（当前最短覆盖子串）
重复直到 right 走完
```

**窗口长度不固定**（3/438/239 是定长窗口，76 是变长窗口）——"覆盖了就缩，缩坏了再扩"。

## 二、两个关键判断

### 1. 怎么判断"窗口覆盖 t"？（两种做法）

| 做法 | 判断方式 | 复杂度 |
|------|---------|--------|
| **用户版：equ 全扫** | 每次遍历 `count_dict`（t 的字符集），检查 `now_dict[key] >= value` 全成立 | O(\|t\|)/次 |
| **标准版：missing 计数** | 维护 `missing` = 还缺多少个字符；右进时若 `need[c]>0` 则 missing-1，缺口清零即覆盖 | **O(1)/次** |

### 2. 为什么"超出需求"不影响 missing？

`need[c]` 可以减成负数（窗口里该字符多出来了）。此时 `need[c] > 0` 为假，缺失不增不减——**只有真正还缺它的时候才计入缺口**。负数 = 富余，不影响覆盖判定。

## 三、标准版代码（missing 计数，推荐背这个）

```python
need = defaultdict(int)
for c in t: need[c] += 1
missing = len(t)          # 还缺几个字符（含重复）
left = 0; result = ""; min_len = float('inf')

for right, c in enumerate(s):
    if need[c] > 0:       # 正好是缺口里的字符
        missing -= 1
    need[c] -= 1          # 窗口计数（可负 = 富余）
    while missing == 0:   # 覆盖达成 → 尝试收缩
        if right - left + 1 < min_len:
            min_len = right - left + 1
            result = s[left: right + 1]
        if need[s[left]] == 0:   # left 退出的是"恰好补齐缺口"的字符 → 缺口加回
            missing += 1
        need[s[left]] += 1
        left += 1
return result
```

**每个字符进出窗口各一次 + O(1) 更新 → 真 O(n)。**

## 四、复杂度

- 时间：标准版 **O(n)**（用户版 O(n·|t|)，|t|≤52 常数所以也能过）
- 空间：O(|t|)（两个计数表）

## 五、一刷 vs 二刷

- 一刷（9-20）：HOT100 收官第 100 题，两次提交 AC；
- 二刷（10-14）：RE → WA → AC 三次演进。思路记得住（右扩左缩 + 记录），但**状态变量同步更新**（min_length）和**辅助代码贴全**这两个坑各踩一次。

## 六、滑动窗口家族（配套复习，4 题打通）

| 题 | 窗口 | 判断方法 | 套路 |
|----|------|---------|------|
| 3 无重复最长子串 | 变长 | dict 记最后位置 | 遇重复跳 left |
| 438 字母异位词 | **定长** | 26 计数数组比较 | 右进左出增量 |
| 239 滑动窗口最大值 | **定长** | 单调队列 | 队首即最值 |
| **76 最小覆盖子串** | **变长** | **missing 计数** | **覆盖→收缩→记录** |

76 是窗口族的"集大成者"——变长 + 计数判断 + 状态维护，啃下它其余三题都顺手了。

## 七、一句话记住

> **最小覆盖子串 = 右扩到覆盖 + 左缩到刚好不覆盖 + 记录；判断覆盖用 missing 计数（O(1)）不用全扫，维护 min_len 必须和记录同步更新。**
