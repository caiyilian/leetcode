# 300. 最长递增子序列 · 解析（二刷）

## 一、题目（中英）

- 中文：最长递增子序列
- English：Longest Increasing Subsequence（**LIS**）
- 难度：中等（进阶要求 O(n log n)）

## 二、核心思路（进阶解：tails 最小尾巴 + 二分）

**问题**：找数组里最长的一段"递增子序列"（子序列 = 保持原顺序挑数，可不连续）。

**O(n²) DP 卡在哪**：`dp[i] = max(dp[j]+1) for j<i 且 nums[j]<nums[i]`——每个 i 必须扫所有 j，不知道"前面最优"在哪。

**进阶关键一步——换状态定义**：
```
tails[k] = 长度恰好 k+1 的递增子序列中，末尾元素的最小值
```
**为什么 tails 天然严格递增**：若 `tails[2] <= tails[1]`，取长度 3 的序列前 2 个，其末尾 ≤ tails[2] ≤ tails[1]，存在比"长度 2 最小末尾"更小的，矛盾 → 严格递增 → **可以二分**。

**处理每个数 x**：
```
i = 二分找第一个 >= x 的位置
若 i == len(tails)：tails.append(x)   # x 比所有尾巴大 → 新长度
否则：tails[i] = x                    # 替换：同长度、更小尾巴 → 给未来留空间
答案 = len(tails)
```

**替换的灵魂**（用 [4,10,4,3,8,9] 体会）：
```
喂 4  → [4]
喂 10 → [4,10]      10 比 4 大 → 新长度
喂 4  → [4,10]      4 换 4，无变化
喂 3  → [3,10]      3 替换 4 → 长度1尾巴变小
喂 8  → [3,8]       8 替换 10 → ⚡ 长度2尾巴变小
喂 9  → [3,8,9]     9 比 8 大 → 新长度！答案 3（3,8,9）
最后一步能凑成长度 3，正是因为第 5 步把 10 换成 8——尾巴越小，将来能接上的数字越多。
```

## 三、代码（用户 AC 版，O(n log n)）

```python
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = [nums[0]]
        for i in range(1, len(nums)):
            if nums[i] > tails[-1]:
                tails.append(nums[i])
            else:
                left, right = 0, len(tails)    # 手写二分：第一个 >= nums[i]
                while left <= right:
                    mid = (left + right) // 2
                    if tails[mid] == nums[i]:
                        break                  # == 直接 break（无需替换）
                    if tails[mid] > nums[i]:
                        right = mid - 1
                    else:
                        left = mid + 1
                else:
                    tails[left] = nums[i]      # for-else：未命中 → 替换
        return len(tails)
```

（参考：`bisect_left(tails, x)` 一行等价——用**第一个 ≥ x**，严格递增不能取等。）

## 四、⚡ 二刷踩坑（WA 一次）

**错误**：`else: tails[-1] = nums[i]`（只替换最后一个尾巴，不做二分定位）。

**为什么错**：`[4,10,4,3,8,9]` 中 4 把 10 替换后 tails 变 `[4,4]` ——**不是严格递增了**：
- 破坏了"有序数组才能二分"的前提（后续代码虽没再用二分，但追加长度会算错）；
- 8 来了比 4 大 → 错误追加 → tails=[4,4,8] → 长度 3？实际 4,4,8 不是递增序列 → 答案被高估。

**教训**：能用 replace 前必须**先定位**——"第一个 ≥ x"才保证替换后数组仍有序。

## 七、一句话记住

> **LIS 进阶 = tails 数组存"每长度的最小尾巴"，严格递增可二分；新数 x 替换"第一个 ≥ x"的尾巴（比所有尾巴大就追加），答案 = len(tails)；⚡ 替换前必须二分定位，无脑替换末尾会破坏单调性。**
