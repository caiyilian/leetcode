## ⚡ TLE → AC 复盘（本次最值钱）

**同一段逻辑，唯一改动是 `*` 分支的短路顺序**：

```python
# TLE 版：消耗 s 的递归在 and 左侧，每条路径都会真的往下钻
return fun(i, j-2) or (fun(i-1, j) and is_fit(i, j-1))

# AC 版：先判断"当前位能不能对上"，对不上直接不钻（短路剪枝）
return fun(i, j-2) or (is_fit(i, j-1) and fun(i-1, j))
```

- `is_fit` 是 O(1) 的字符比较，`fun(i-1, j)` 是递归——**把便宜的判断放前面**，`is_fit` 为 False 时（当前字符对不上），`and` 右侧的递归根本不执行；
- 这个剪枝把这题从指数级拉回可行范围（本题无记忆化也能过，23ms）；
- **通用教训**：递归里想剪枝，把"开销小的能早退的判断"放在 `and` 左侧 / `or` 右侧，让昂贵的递归尽量被短路。
