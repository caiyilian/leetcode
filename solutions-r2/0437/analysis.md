# 437. 路径总和 III · 解析（二刷）

## 一、核心思路：前缀和 + 哈希 + 回溯

**题目**：数出树上"向下路径"中节点和 = targetSum 的条数（路径起点不必是根，方向必须向下）。

**暴力是 O(n²)**（每个节点当起点，向下 DFS）。**前缀和把"路径和"变成"两个前缀和之差"**：

```
       10               从根到每个节点的前缀和 acc：
      /  \              10→10    10→5→3=18   10→5→2=17  10→-3→11=18 ...
     5   -3             路径 i→j 的和 = acc_j - acc_i
    / \    \            要找 acc_j - acc_i = targetSum
   3   2   11           ⇔ acc_i = acc_j - targetSum
  / \   \
 3  -2   1             所以只要知道"acc_i 出现过几次"，当前节点就多了几条路径
```

## 二、代码（用户 AC 版）

```python
result = [0]
hash_map = {0: 1}                    # 前缀和 → 次数；{0:1} = 虚拟起点

def fun(root, acc=0):
    if root:
        acc += root.val                                # 当前前缀和
        result[0] += hash_map.get(acc - targetSum, 0)   # ★ 查差值
        hash_map[acc] = hash_map.get(acc, 0) + 1        # 记录自己
        fun(root.left, acc)
        fun(root.right, acc)
        hash_map[acc] -= 1                              # ★ 回溯撤销

fun(root)
return result[0]
```

## 三、三个关键细节（⚡ 必考点）

1. **查差值** `hash_map[acc - targetSum]`：出现几次 = 有几个起点凑成目标路径——这是 O(n) 的灵魂（不用枚举路径对）；
2. **{0:1} 虚拟起点**：路径可以从根开始（起点之前前缀和视为 0），没有它根开头的路径会漏；
3. **回溯撤销** `hash_map[acc] -= 1`：递归返回时把自己从前缀和集合里删掉——**路径必须沿一条根链向下，左子树的计数不能出现在右子树里**（跨子树会数出非法路径）。

## 四、为什么需要回溯（对比 560）

560 是数组（线性），前缀和集合一直累积就行；437 是树（分叉），**不撤销会把"兄弟子树"的前缀和也算进来**——路径必须连续向下。这是树版前缀和与数组版唯一的本质区别。

## 五、复杂度

- 时间：O(n)
- 空间：O(n)（哈希最多存一条根链长度）

## 六、一刷 vs 二刷

- 一刷（9-15）：AC ×2（⚡⚡⚡ 机考前一天重点标记：前缀和+哈希+回溯，与 560 配套）；
- 二刷（10-27）：**10-25 卡住 → 10-27 一次 AC**——状态到了三件套直接写对，心法内化。
