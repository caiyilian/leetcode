# 56. 合并区间 · 解析（二刷）

## 一、核心思路：排序 + 一趟遍历合并

```
① 按起点排序——相邻区间才有合并可能
② 从左到右遍历：
   不相交（cur[1] < next[0]）→ 当前区间收进结果
   相交/包含（cur[1] >= next[0]）→ 合并成 [cur[0], max(cur[1], next[1])]
```

**为什么必须排序**：合并需要知道"哪个区间在哪个前面"，排序后只需比较相邻两个——一趟 O(n) 搞定。

## 二、两种等价写法

```python
# 写法 A（用户版）：合并写到"下一个位置"，最后统一收尾
intervals.sort(key=lambda x: x[0])
result = []
for i in range(length - 1):
    if intervals[i][1] < intervals[i+1][0]:
        result.append(intervals[i])            # 不相交，收走
    else:
        intervals[i+1] = [intervals[i][0], max(intervals[i][1], intervals[i+1][1])]
result.append(intervals[-1])

# 写法 B（标准版）：result 最后一个当"当前合并对象"
intervals.sort(key=lambda x: x[0])
result = [intervals[0]]
for s, e in intervals[1:]:
    if result[-1][1] < s:
        result.append([s, e])
    else:
        result[-1][1] = max(result[-1][1], e)
```

**B 更简洁**：`result[-1]` 天然是"当前正在合并的区间"，`new_start > result[-1].end` 则新开一段，否则扩展右边界。A 的"写下一位置"逻辑等价，还省一次 `result[-1]` 索引。

## 三、三个边界细节

| 场景 | 处理 |
|------|------|
| **完全包含** `[1,4]` + `[2,3]` | `cur[1]=4 >= 2` → 合并 `[1, max(4,3)] = [1,4]` ✅ |
| **紧贴相邻** `[1,4]` + `[4,5]` | `4 >= 4` → 合并 `[1,5]`（题目要求相邻即合并）✅ |
| **单元素 / 空输入** | 单元素直接返回；空输入需守卫（力扣约束 len>=1） |

## 四、复杂度

- 时间：**O(n log n)**——排序主导（合并本身 O(n)）
- 空间：O(n)（结果集）或 O(1)（原地，额外空间）

## 五、为什么 O(n log n) 是下界

合并必须知道区间之间的顺序关系——**不排序就无法确定任意两个区间谁先谁后**，而排序的理论下界就是 O(n log n)。所以"排序 + 一趟"就是最优。

## 六、一刷 vs 二刷

- 一刷（9-12）：2 版演进（排序 + 遍历，就地更新右边界 + 去掉多余 min）；
- 二刷（10-15）：**直接写出排序 + 原地合并，一次 AC**——套路已内化。

## 八、一句话记住

> **合并区间 = 按起点排序 + 一趟相邻比较：相交就并（右界取 max），不相交就收。O(n log n) 是下界。**
