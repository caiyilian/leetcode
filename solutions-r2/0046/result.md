## 是否最优解？✅ 是

| 考察点 | 结论 |
|--------|------|
| 时间复杂度 | ✅ O(n×n!)——n 个位置的排列数 n!，每排列复制 O(n) |
| 空间复杂度 | ✅ O(n)（递归栈 + path + used） |
| 正确性 | ✅ 官方示例 + n=1/空列表边界，**5 千组随机对拍**（vs 标准 used 数组 + itertools 双参照）0 不一致 |
| 思路 | ✅ 回溯 + used 标记（每次从全部数中选未用过的）= 官方标准解 |

## 解法核心：排列用 used 标记（可回头）

```python
for n in nums:        # ⚡ 每次都从全部数里选（排列要"回头"）
    if n in exist:
        continue      # 已用过 → 跳过
    exist.add(n)      # 选
    path.append(n)
    path = fun(path, exist)
    path.pop()        # 撤销
    exist.remove(n)
```

**与 39 组合总和的本质区别**：
- **39 组合**：`[2,3]` 和 `[3,2]` 算同一个 → **start 不回头**，只从当前及之后选；
- **46 排列**：`[1,2,3]` 和 `[1,3,2]` 算不同 → **used 标记回头**，每次都从全部数里选没用过的。

| | 39 组合 | 46 排列 |
|---|---|---|
| 去重方式 | start 索引不回头 | used 集合/数组标记 |
| 每次选的范围 | candidates[start:] | 全部未用 nums |
| 关键 | 递归传 start | exist.add/remove 成对 |

## 其他要点

- **`exist` 是 set**：`in` 判断 O(1)；标准版用 `used = [False]*n` 按下标（更省，扩展到大数重复场景更稳）；
- **`path.copy()` 收集**：path 共享引用，必须 copy（39 同款教训）；
- 边界：空列表返回 []，n=1 返回 [[n]]。
