# 142. 环形链表 II · 解析（二刷）

## 一、核心思路：141 的框架 + 二次相遇

141 只问"有没有环"（相遇就 True）；142 要"环的入口在哪"。解法是 141 的延续：

```
① 快慢指针追及（同 141）：
   - 无环 → 快指针到 None → return None
   - 有环 → 两指针必然相遇，记录相遇点
② 相遇后：slow 重置回 head，两指针都改为每次 1 步
③ 再次相遇的位置 = 环入口
```

## 二、为什么第二次相遇点就是入口（数学推导，大白话版）

设三段距离：

```
head → 入口：a 步
入口 → 相遇点：b 步
环长：L 步（b 是入口到相遇点那一段，剩下的环是 L-b）
```

相遇时：slow 走了 a+b；fast 走了 2(a+b)。fast 比 slow 多绕了整数圈：

```
2(a+b) = (a+b) + kL   →   a+b = kL   →   a = kL - b
```

**大白话**：从相遇点出发绕一圈回到相遇点是 L 步，而"从入口到相遇点"只要 b 步——所以从相遇点**往回退 b 步**就是入口；同理，从 head 走 a 步也是入口。把 slow 放回 head、fast 留在相遇点，两个"还差 a 步到入口"的指针同速走，必然在入口汇合。

## 三、⭐ 步数可以是 0（一刷重点标记，二刷天然免疫）

当 **a = 0**（head 本身就是环入口，如 `[1,2]` pos=0）时：

- 相遇点在环内某处，slow 重置回 head 后，head **已经是**入口；
- 如果写的是 `while True: p_slow = p_slow.next; p_fast = p_fast.next; if p_slow is p_fast: return ...`（先移动后判断），slow 会先离开入口走一步，错过正确位置；
- 正确写法：**`while p_slow is not p_fast`（先判断后移动）**——步数可以是 0，一进循环发现已经在入口，直接返回。

## 四、复杂度

- 时间：O(n)——追及 O(n) + 二次相遇 O(a) ≤ O(n)
- 空间：O(1)——两个指针

## 五、一刷 vs 二刷

- 一刷（9-13）：独立快慢指针 + 二次相遇，RE 1 次 → AC ×2（踩过"先移动后判断"的坑，标注"步数可以是 0"）；
- 二刷（10-18）：**一次 AC 无失败**，`while p_slow is not p_fast` 先判断后移动一步到位——一刷的坑没再栽。
