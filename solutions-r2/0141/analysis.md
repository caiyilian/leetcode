# 141. 环形链表 · 解析（二刷）

## 一、核心思路：快慢指针追及

两人同向跑步，快的每秒 2 步、慢的每秒 1 步：

- **操场是环**：快的人每圈多跑 1 步，迟早追上慢的人 → `True`
- **直道**：快的人先跑到头（None）→ `False`

```
p_fast = head   # 快指针，每次 2 步
p_slow = head   # 慢指针，每次 1 步

while p_fast and p_fast.next:   # 无环时快指针先越界 → 循环结束
    p_slow = p_slow.next
    p_fast = p_fast.next.next
    if p_slow is p_fast:        # 身份比较：同一个节点
        return True
return False
```

## 二、为什么必然相遇（而不是"快指针跳过慢指针"）

环内相遇是**数学上必然**的：

- 进入环后，快指针相对慢指针的速度是 **1 步/轮**（2 - 1）
- 相对速度恒定 → 相对距离单调递减 → 一定会在某轮追到（快慢指针不会互相"错过"，因为环是闭合的，减到 0 即相遇）

简单说法：**快的比慢的多走 1 步/轮，环长有限，差 0 是必达的**。

## 三、两个细节

1. **空链表 / 单节点**：`while p_fast and p_fast.next` 天然处理——head 为 None 或只有一个节点时循环不进入，直接 False，**不用特判**（206 的 AttributeError 坑的相反面）；
2. **用 `is` 不用 `==`**：`p_slow == p_fast` 会比较节点值（ListNode 无 __eq__ 时退化为身份比较，碰巧对；但语义上"同一个节点"就该用 `is`）。

## 四、复杂度

- 时间：O(n)——无环时快指针走完链表即止；有环时快指针进入环后最多环长轮内相遇，总步数 O(n)
- 空间：O(1)——两个指针

## 五、一刷 vs 二刷

- 一刷（9-13）：独立快慢指针，两次 AC；leetgo manual question 本地测试报错（属正常，在线为准）；
- 二刷（10-18）：**一次 AC 无失败**，还自己把相遇判断升级为 `is`——对"指针题比的是节点身份"理解到位了。

## 七、一句话记住

> **环形链表 = 快慢指针追及：无环快指针先到 None，有环快指针必追上慢指针（相对速度 1 步/轮）；相遇用 `is` 身份比较；`while p_fast and p_fast.next` 天然空安全不用特判。**
