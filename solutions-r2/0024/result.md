## 用户自己的优化直觉 → 证实正确

用户 AC 后主动提出："`if p2 is None: break` 应该可以优化"——**判断完全正确**。原版：

```python
while prev and prev.next:
    p1 = prev.next
    p2 = p1.next
    if p2 is None:      # ← 循环内的"没有一对可交换"判断
        break
    ...
```

`break` 其实是在表达"当前没有完整一对就退出"，这个条件**并进 while 条件更自然**：

```python
while prev.next and prev.next.next:   # 有 p1 且有 p2 才进入
    ...
```

同时 `prev and` 也可省（prev 只会是 dummy 或上一轮的 p1，永不为 None）。三处检查合一，逻辑等价、更干净。

**这是很好的代码嗅觉**——"循环体内的 break 往往可以吸收进循环条件"。
