# 23. 合并 K 个升序链表 · 解析（二刷）

## 一、核心思路：把 K 个"两两合并"，轮次减半

K 条链不能像 21 题那样一次比完（要同时看 K 个头，就得用堆）。但如果**两两合并成一条**，每轮把链表数量减半，log k 轮后剩一条——这就是**分治**：

```
k=3:  [1,4,5] [1,3,4] [2,6]
第1轮: merge([1,4,5],[1,3,4]) = [1,1,3,4,4,5]
       [2,6] 单独留下（奇数）
第2轮: merge([1,1,3,4,4,5], [2,6]) = [1,1,2,3,4,4,5,6]
```

**为什么比"顺序逐个合并"快**：顺序合并是第一条和第二条合成一条、再和第三条合……每轮都要遍历已合成的大链，总共 O(kN)；分治是**每轮只合并等长的对**，共 log k 轮，O(N log k)。

## 二、代码骨架（用户版）

```python
while length > 1:                      # 直到只剩一条
    for i in range(length // 2):       # 两两配对合并
        lists[i] = merge2(lists[2*i], lists[2*i+1])
    if length % 2 == 1:                # 奇数条：最后一条留到下一轮
        lists[length // 2] = lists[length - 1]
        length = 1 + length // 2
    else:
        length = length // 2
return lists[0]
```

两个细节：
- **原地紧凑**：合并结果写回 `lists[i]`，不新建数组——O(1) 空间；
- **奇数处理**：`[a,b,c]` 合并 `a,b` 得 `ab`，`c` 单独搬到 `lists[1]`，下一轮 `[ab, c]` 再合并。`length = 1 + length//2`（如 3 → 2，5 → 3）。

`merge2` 就是 21 题的哨兵归并（dummy + 双指针挑小 + 尾部接剩余）。

## 三、为什么是 O(N log k)

每轮合并后链表数减半，共 log k 轮；每轮所有节点恰好被处理一次，每轮 O(N)。总 O(N log k)。

## 四、复杂度

- 时间：O(N log k)
- 空间：O(1)（原地）+ merge2 的 O(1) 指针

## 五、一刷 vs 二刷

- 一刷（9-14）：v1 顺序合并 O(kN) → TLE/WA → v2 分治 O(N log k) 5 次提交演进；**实测 7.7 倍 ≈ log₂200 验证复杂度**；
- 二刷（10-22）：直接 v2 分治一次 AC（8ms），奇数补位 + 原地紧凑一步到位——**分治减半 + 21 归并组件完全内化**。

## 七、一句话记住

> **合并 K 个升序链表 = 分治两两合并：每轮 merge2 配对合并、k 减半，log k 轮 O(N log k)；奇数条把最后一条搬到中间留到下一轮；merge2 就是 21 题哨兵归并。**
