# 146. LRU 缓存 · 解析（二刷）

## 一、核心思路：哈希定位 + 双向链表维护顺序

LRU = 最近最少使用。需要两个能力：
1. **O(1) 找到 key 对应的节点** → 哈希表 `key → node`；
2. **O(1) 调整访问顺序** → 双向链表（头=最近使用，尾=最久未用），摘除/插入都是常数次指针操作。

```
forward(哨兵头) ⇄ 最近使用 ⇄ ... ⇄ 最久未用 ⇄ backward(哨兵尾)
     ↑ 新访问/新插入都放这里           ↑ 容量满就删这里
```

## 二、为什么必须双向链表（而不是单向）

- **get 命中**：要把节点移到最前，需要把"它前面的节点"指向"它后面的节点"——单链表做不到 O(1) 找到前驱，双链表 `node.before` 一步到位；
- 摘除（4 行）：`before.next = next; next.before = before`；
- 插入头（4 行）：`node.before = head; node.next = head.next; head.next.before = node; head.next = node`。

**记忆口诀**："先摘除（两行），后插头（四行）"——插头四行的顺序是：改 node 自身两个指针 → 改旧首节点的 before → 改 head 的 next（最后改 head 的 next，避免提前断开）。

## 三、双哨兵 forward/backward

空链表、删头节点、删尾节点这些边界，用**哨兵头尾节点**全部消掉：
- `forward.next` 永不为 None（至少是 backward）→ 插头不用判空；
- `backward.before` 永不为 None → 删尾（最久未用）不用判空；
- 空缓存时 forward 和 backward 互相指着，逻辑依然成立。

## 四、RE → AC：节点里必须知道"自己是哪个 key"

双向链表节点存的是 **value**（`ListNode2(value)`），但驱逐时要从 `hash_map` 里删 key——**val ≠ key**（`put(1,99)` 节点 val 是 99，key 是 1）。RE 版用 `hash_map.pop(delete_node.val)` 删错了键。

**修复方案对比**：
- ❌ 双哈希表：`hash_map2[node] = key` 反查（用户 AC 版用的，功能对但多一张表）；
- ✅ **节点带 key 字段（标准）**：`ListNode2(value, key=key)`，驱逐时 `hash_map.pop(delete_node.key)`——一张表闭环，官方常见写法。

**结论：LRU 标配 = 一个哈希表 + 双向链表，节点里存 key。**

## 五、get/put 的 O(1) 论证

| 操作 | 哈希 | 链表 | 合计 |
|------|------|------|------|
| get 命中 | 查 key→node O(1) | 摘除+插头 8 次指针 O(1) | **O(1)** |
| put 命中 | 查 + 改 val O(1) | 同 get 前移 O(1) | **O(1)** |
| put 未命中 | 插入 O(1) | 插头 O(1) | **O(1)** |
| 驱逐 | pop 反向映射 O(1) | 删尾 O(1) | **O(1)** |

## 六、复杂度与空间

- 时间：get / put 均 O(1)（含驱逐）
- 空间：O(capacity)——hash_map + hash_map2 + 链表各 capacity 个条目。**这是标准量级**（力扣 29.1MB 与官方典型一致），不是"占用过多"。

## 七、一刷 vs 二刷

- 一刷（9-14）：纯看视频想象实现，未本地测，一次 RE 后 AC（哈希+双向链表+哨兵结构一次成型）；
