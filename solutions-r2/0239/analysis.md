# 239. 滑动窗口最大值 · 解析（二刷）

## 一、核心思路：单调队列（monotonic queue）

窗口滑动时，用 deque 维护**窗口内"可能成为最大值"的候选集合**，且保持**单调递减**：

```
队首 ← [最大, 次大, ..., 最小] → 队尾
         (候选序列单调递减)
```

**两个操作**（每次滑动新数 i 进来）：

```
① 过期清理：if q[0] == i - k: q.popleft()      # 队首滑出窗口才弹
② 挤掉更小：while q and nums[q[-1]] < nums[i]: q.pop()   # 队尾比新数小的永无出头之日
③ 入队：q.append(i)
④ 答案：nums[q[0]]                              # 队首即窗口最大值
```

## 二、为什么"挤掉更小"是安全的（贪心排除）

新数 `nums[i]` 比队尾某元素更大**且更晚出窗口**——在那个更小元素出窗口之前，新数始终存在且更大，所以它**永远不可能成为窗口最大值**。留着它只会浪费空间，直接 pop。

**单调递减**的候选序列保证：队首 = 当前窗口最大值，且所有被跳过的元素都不可能在将来翻盘。

## 三、两个关键细节（用户二刷踩点）

| 细节 | 为什么 |
|------|--------|
| **popleft 带条件** `q[0]==i-k` | 被挤掉的元素早不在队列里，队首往往不是"窗口最左元素"——无脑 popleft 会误删最大值 |
| **存下标不存值** | 只有下标能判断"是否滑出窗口"（`q[0] == i-k`）；存值无法判断过期 |

## 四、deque 底层与"只有两端快"（用户疑问解答）

- CPython 的 deque = **双向链表 + 分块数组**（每块 64 元素，块间指针相连）；
- 两端操作（append/pop/popleft/appendleft）只动块内指针 → **O(1)**；
- **中间索引 `q[i]` 要顺着指针走到对应块再遍历 → O(n)**；
- 所以：**deque 牺牲"任意位置快速访问/切片"（list 有 O(1) 索引、切片），换来"两端都 O(1)"**；
- list 相反：连续内存索引 O(1)，但头部插入/弹出要全体搬迁 O(n)。

**单调队列题只用 `q[0]` 和 `q[-1]`**——正好只踩 deque 最强的地方，劣势完全不碰。

## 五、复杂度

- 时间：O(n)（每个下标入队一次、出队至多一次）
- 空间：O(k)（队列长度 ≤ 窗口大小）
