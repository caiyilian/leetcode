# 189. 轮转数组 · 解析（二刷）

## 一、核心思路：三次反转（O(1) 空间最优解）

**核心性质**：一个数组反转两次 = 原地不动（两次反转抵消）。

右移 k 的分解：整体右移 k ⟺ "前 n-k 段"和"后 k 段"对调位置。用反转实现对调：

```
[1,2,3,4,5,6,7] k=3（右移 3，后 3 个 [5,6,7] 到前面）
① 整个反转       → [7,6,5,4,3,2,1]
② 前 k=3 个反转  → [5,6,7,4,3,2,1]
③ 后 n-k=4 反转  → [5,6,7,1,2,3,4] ✅
```

**为什么三次反转一定对**：
- ① 后，原数组的后 k 个（即要挪到前面的）到了**最前面**，但顺序反了；
- ② 把前 k 个反转回来，恢复正确顺序；
- ③ 把剩下的 n-k 个反转回来，恢复正确顺序。
→ 三段各自回到原位，整体完成右移。

**代码 5 行**：

```python
def rotate(nums, k):
    n = len(nums)
    k %= n                       # 防 k>n；k=0 时三次反转都是无操作，天然安全
    nums[:] = nums[::-1]
    nums[:k] = nums[:k][::-1]
    nums[k:] = nums[k:][::-1]
```

## 二、你踩的两个坑：块交换法（block swap）

你的原始思路是块交换：把尾部 k 个元素整块换到头部。大方向对，但有两个致命边界：

### 坑 1：TLE——k=0 死循环

```python
k = k % length          # 若 k 是 length 整数倍 → k=0
while length - start > k:
    for i in range(k): ...    # range(0) 空转
    start += k                # start += 0 → 永不前进 → 死循环
```

**教训**：while 循环里"步进量"必须保证前进——`start += k` 在 k=0 时失效。

### 坑 2：WA——余数收尾错位

```
[1,2,3,4,5,6,7,8] k=3：8 % 3 = 2
循环结束时还剩 2 个没轮转，但 index2 = length-k+i 指向错位
→ 结果 [6,7,8,1,2,5,4,3]（尾巴 [5,4,3] 顺序反）期望 [6,7,8,1,2,3,4,5]
```

块交换的正确实现需要处理"剩余长度和 k 的关系"（gcd 分组交换），**极易写错**。三次反转没有这个分支。

## 三、复杂度

- 时间：O(n)（三次反转各 O(n)）
- 空间：O(1)（原地）

## 四、三种写法对比（一刷 vs 二刷）

| 写法 | 时间 | 空间 | 特点 |
|------|------|------|------|
| 切片拼接（一刷最快） | O(n) | **O(n)** | `nums[:] = nums[-k:]+nums[:-k]`，最快但不满足 O(1) 进阶 |
| 手写反转（一刷） | O(n) | O(1) | 自己写 reverse 函数，慢 4~5 倍 |
| **三次反转（二刷）** | O(n) | **O(1)** | 标准答案，兼顾简洁与进阶要求 |

## 五、一句话记住

> **轮转数组 = 三次反转：全反 → 前 k 反 → 后 n-k 反；先 k%=n 防边界。块交换的余数收尾易错，面试直接背三次反转。**
