# 128. 最长连续序列 · 二刷解析

## 题目回顾

给一个未排序的整数数组，找出**数字连续**的最长序列的长度。**要求 O(n)**（排除排序法）。

## 核心思路：set + 只从"起点"数

**一句话**：把数组扔进 set（去重 + O(1) 查找）；遍历时只有 `n-1` 不在集合里（n 是序列起点）才往后延伸——每个序列恰好数一次，总 O(n)。

```
nums = [100, 4, 200, 1, 3, 2]  →  set = {1,2,3,4,100,200}

遍历集合：
  100：99 不在 → 起点，数 101? 不在 → 长度 1
  4  ：3 在！→ 不是起点，跳过（避免重复数 1→2→3→4）
  200：199 不在 → 起点，数 201? 不在 → 长度 1
  1  ：0 不在 → 起点，数 2,3,4 → 长度 4 ← 答案
```

## 为什么这样是 O(n) 而不是 O(n²)

暴力法：每个数都往后数 → 最坏 O(n²)（如 `[1,2,3,...,n]` 每个数都数一遍全序列）。
起点法：**只有序列起点才数**，每个序列只数一次，所有 n 个元素总共被"延伸访问"一次 + 被"起点判断"访问一次 → **O(n)**。

**这是本题核心 trick**：`n-1 not in hash_set` 一行，把 O(n²) 砍到 O(n)。

## 两个易错点（二刷重点）

1. **空数组**（本次 WA 的根因）：
   ```python
   max_length = 1      # 假设至少有一个元素
   return max_length   # 空数组时返回 1 ❌
   ```
   → 需要 `if not nums: return 0` 特判。**"初始值假设非空" vs "输入可能为空"是经典边界坑**。

2. **重复元素**：原数组可能有重复（如 `[1,2,0,1]`）——用 `set(nums)` 天然去重，重复元素不会把长度数多。如果遍历原数组而不是集合，`1` 出现两次会多统计。

## 思路来源（为什么想到 set + 起点）

- **要求 O(n)** → 不能排序 → 需要 O(1) 判断"x 在不在" → **set**；
- **避免重复统计** → 只在起点数 → **`n-1 not in set` 判断**。
- 两步推理链：复杂度要求 → 数据结构 → 去重策略。这类"先定复杂度，再选结构"的思考顺序，二刷比一刷更顺。
