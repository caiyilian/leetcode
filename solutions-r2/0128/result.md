## 失败提交记录（WA 753938713）

**唯一差别：少了空数组特判**

```python
# WA：max_length = 1，没有空数组特判
max_length = 1
for n in hash_set:        # nums=[] 时集合空，循环不执行
    ...
return max_length         # 返回 1 ❌（期望 0）

# AC：加一行
if len(nums) == 0:
    return 0              # ✅
```

**教训**：`max_length` 初始化为 1 时，**空输入会错误返回 1**。"初始值假设至少有一个元素"但输入可能为空——这类边界 bug 很典型，检查边界条件时把"空输入"单独列一项。

## 解法一句话

**哈希集合 + 只从起点数**：`set(nums)` 去重；遍历集合时，只有 `n-1` 不在集合里（n 是序列起点）才往后数——保证每个序列只数一次，总 O(n)。

- 时间复杂度：**O(n)**
- 空间复杂度：**O(n)**

## 验证

- **对拍**：2 万组随机（含重复、负数、空数组），与排序法对照，**0 不一致** ✅
- 样例 `[100,4,200,1,3,2] → 4`、`[0,3,7,2,5,8,4,6,0,1] → 9`、`[] → 0`、`[1,2,0,1] → 3` 全部正确

## 备注（二刷）

- 与一刷定稿解法相同（哈希集合 + 起点计数），核心 trick `n-1 not in hash_set` 一次想到位；
- 一刷曾 TLE（暴力 O(n²)），二刷直接 O(n)，说明复杂度意识已内化；
- 二刷新踩的坑：空数组特判（一刷时可能没踩或已处理）。
