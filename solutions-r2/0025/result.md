## 本地先错一版 → 修复后 AC（本次宝贵教训）

### 错误版本：漏了 `prev.next = 新头`，每轮丢一个节点

用户本地实现（test.py）第一版：

```python
else:  # 没有发生break
    p_next = p_last.next
    p_last.next = None
    p1, p_last = reverse_node(p1)   # 返回 (新头, 新尾)
    p_last.next = p_next            # 新尾接下一组
    prev = p_last                   # prev 前进到新尾
    continue
```

**缺了 `prev.next = p1`（把前驱接到反转后的新头）**。反转后 `p1`=新头、`p_last`=新尾都是局部变量，但 **`prev.next` 还指着旧头**。旧头反转后变成新尾，于是：

```
[1,2,3,4,5] k=2：
第1轮：prev(dummy).next 仍=1，而 1 已是新尾 → 2 悬空丢失 → 结果 [1,3,4,5]
第2轮：prev(1).next=3，而 3 又是新尾 → 4 丢失 → [1,3,5]
```

**症状**：所有用例每轮丢一个节点（`[1,2,3,4,5]` k=2 → `[1,3,5]`，k=3 → `[1,4,5]`）——不是边界错，是主循环每轮都漏同一件事。

### 修复：加一行

```python
p1, p_last = reverse_node(p1)
prev.next = p1          # ★ 关键：prev 接到新头
p_last.next = p_next
```

### 教训（已沉淀）

**"反转子链"必须同时维护三个"接缝"**：前驱→新头、新尾→后继、前驱指针前进。漏掉第一个（`prev.next`），整条子链就从链表上"掉"下来了——局部变量里能看到反转结果，但全局链里它悬空了。这正是"指针操作要时刻问：现在谁还指着你？"的经典案例。

对比一刷 AC 版：`p_prev.next, p_now_last = self.reverse_list(p_prev.next)` 一步同时更新了前驱的 next 和组尾——一刷写对过，二刷简化时漏了，**"简化不意味着可以省关键连接"**。
