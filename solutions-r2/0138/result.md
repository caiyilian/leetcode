## 交错法 O(1)（力扣 follow-up，本次补归档）

**核心思想：用"位置"代替哈希表**——新节点直接插在原节点后面，`原.next` 就是它的拷贝，映射由链表结构本身承载。

三步：
1. **穿插**：`A → A' → B → B' → C → C'`（每个原节点后插拷贝）；
2. **补 random**：`cur.next.random = cur.random.next`——原 random 指向的节点的拷贝，就在它后面；
3. **拆链**：奇数位是原链（恢复如初），偶数位是新链（返回值）。

**为什么省掉哈希表**：哈希表的作用是"给定原节点找拷贝"，交错法让拷贝**物理上紧挨着原节点**，找拷贝 = 走一步 next。这就是"用结构代替哈希"。

**拆链坑**：先保存 `clone.next` 再断开，否则拆着拆着把另一条链也弄丢；`random = None` 的节点不处理（`if cur.random:` 守卫）。

## 两个插曲（用户踩坑记录，都很有价值）

### 插曲 1：`hash_map = {None: None}` 忘写 → random=None 报错

第一版没预置 `{None: None}`，当节点的 `random` 指向 `None` 时：

```python
new.random = hash_map[p.random]   # p.random = None，hash_map 里没有 None 这个键
# ❌ KeyError: None
```

**修复**：初始化时预置 `hash_map = {None: None}`，让"None → None"也能查表。

**教训**：**键为 None 的边界要主动预置**——哈希表方案里，凡是有"空值也要查表"的场景，先把空值映射放进去，避免 KeyError。

### 插曲 2：第一个 while 忘 `p = p.next` → 内存超出限制（MLE）

第一版复制 next 链时忘了前进 `p = p.next`，导致 `while p` 死循环——**同一个节点被无限复制**，构造了无限长的链表，直接 MLE（内存超限）。

**教训**：**链表遍历循环里，`p = p.next` 是保命行**——忘了它，`while p` 永不退出，输出无限长。这和"指针题先想清楚怎么前进"是同一个心法。

## 深拷贝三验证点（一刷沉淀，二刷沿用）

力扣判题会检查三点（对拍也用它验证）：
1. **值链一致**——`copy.next` 走一遍，值与原链相同；
2. **非同一对象**——新节点不能是原节点（`copy is not orig`）；
3. **random 指向正确**——`copy.random` 与 `orig.random` 的**相对位置**一致（不能指向原链节点）。
